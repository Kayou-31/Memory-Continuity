# 记忆预算：给完整的人物留空间，也守住每次请求的边界

人物原稿可以很长，一次对话仍需要选择。这一版把 **32,768 token** 作为显式启用的新记忆总预算：人物、情境、关系、往事、未完成的事、全局记忆、旧记忆包装和记忆工具结果共用它。不是每层各拿 32K。

在空白根会话中操作：

```text
/memcont budget set {}
/memcont budget show
/memcont injection preview 今天想聊的话题
```

有历史时先 `/memcont continue-clean`，在宿主选择返回的新会话。`budget set` 不能偷偷重解释旧会话。首次启用前保存原 journal 的 `.pre-budget-v2-backup`；它只是会话备份，不替代完整 profile 备份。

默认层预算如下。总额还有包装、工具及已有记忆占用，某层的额度不保证每次都能用满。

| 层 | token 上限 |
| --- | ---: |
| 我是谁 | 6,144 |
| 此刻的处境 | 4,096 |
| 我与重要的人 | 4,096 |
| 与此有关的往事 | 12,288 |
| 尚未完成的事 | 4,096 |

可以在干净会话显式修改，例如：

```text
/memcont budget set {"limitTokens":32768,"layers":{"self":12000,"recollection":12000}}
```

原 `injection.budgets` 与旧 `RuntimeBudget` 仍保留原有字节估算语义；新 `layers` 只在 `memcont.memory-budget/v2` 中生效。`budget set null` 显式回到旧模式，同样需要空白根会话。

## 计量方式会直接显示

- **tokenizer-text**：目前只匹配完整模型名 `deepseek-ai/DeepSeek-V3.2`。使用随包附带、校验哈希的本地 tokenizer，不下载权重，也不联网计数。provider、model、词表修订与预算一起绑定。
- **conservative-utf8**：其他模型以及 `deepseek-chat` 等可变别名暂按 UTF-8 字节保守计量。中文会更早达到上限；界面和状态明确标示降级，不把字节称作精确 token。
- provider/model 改变后，旧绑定不能继续发送。需要干净续接并重新 `budget set`，不能用旧 tokenizer 证明新模型的容量。

精确指 **每个已选文本片段的本地 tokenizer 计数**，不是供应商计费或隐藏聊天模板的精确计数。工具声明和宿主包装按实际序列化内容计入；重复发送的片段重复占用。没有可靠 tokenizer 的整请求部分继续保留保守门禁，模型总容量、输入限制与动态输出预留仍可提前拒绝请求。

## 放不下时会发生什么

可选记忆在组装阶段有限次退让；必需身份、边界、冲突和原始历史不会被悄悄裁掉。发送前再次计量实际消息。旧工具结果不会因为本轮没有选中就自动消失；需要更多空间时明确干净续接。

普通搜索和正文读取在**返回结果认证之前**缩小页面，游标只前进实际返回的范围，Unicode 码点保持完整。搜索固定集合不会混进随后追加的记录。认证之后不裁正文，也不拿更新后的状态替旧结果背书。

共同日记列表可以减少本轮返回项；单篇日记暂保持完整返回，装不下就明确拒绝。AI 写日记前预留回执空间；发布后若回执不能确认，会按持久化不确定处理，检查已保存日记再决定后续操作，不自动重发。

## 已知边界

这次没有开启自动摘要、自动采纳或会话压缩。计数器只按需加载一份，长历史的多次计量仍会增加 CPU 与内存开销；持续数月的大型人物库和移动设备尚未完成负载验证。32K 不等于所有模型都能承受，也不意味着任何时候都应塞满。

词表来源、许可证与固定向量说明见 [tokenizer 来源](../assets/tokenizers/README.md)。实际测试和兼容性证据见 [开发结果](framework-evolution-2026-10-25/RESULTS.md)。

独立核心在没有可信宿主分类器时，会把整个请求保守计入记忆额度；不能靠传入一个空的“记忆列表”绕过限制。DSH 的分类来自已认证的实际历史，并与请求对象、内容哈希、人物权限及准备包绑定。准入期间原请求变化会被拒绝。记忆工具使用串行执行，避免同轮多个工具重复占用同一份剩余额度。
