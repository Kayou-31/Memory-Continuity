## AI 经历如何进入工作台

开关默认关闭。用户开启后，宿主在当前聊天中提供提案工具，模型可在重要事件、明确约定、场景结束或纠正时提交描述、认知类型、理由和精确原句。核心核对当前人物/会话/输入和允许的原文窗口；猜测不会被自动改写成事实。

候选与正式经历分开保存。工作台先展示原句、来源位置与理由；取消不写入，采纳才创建正式事件，拒绝保留决定。同一输入、相同内容重复提案复用原候选，不创建第二条；同一输入换内容返回幂等冲突。无关追加不会让既有候选失效，原证据被撤回或删除则不可继续读取、采纳或认证。

每个人物在当前人生线的提案准入有五分钟间隔、滚动二十四小时八次上限、三十二条待审上限；每份最多八处证据，每处原句最多 2048 UTF-16 字符。准入先持久预扣，记录只含身份摘要、时间和提案 hash，不含对话正文；撤回原话不退还额度。预扣后写入失败可能消费一次额度，相同输入/内容重试复用原预扣。人物 origin 被删除后，相应元数据遵循原有依赖失效。

宿主工具声明在首轮固定并保存到 journal，避免中途增删工具产生无法认证的历史。开始聊天时未启用此功能，需要开启后使用新会话；关闭立即拒绝新写入。候选写成功后，无论是回执保存失败、并发人工审阅造成版本变化，还是关闭/最终容量变化导致回执无法认证，都报告 `persistence_uncertain` 并拦截后续模型请求；可诊断并干净续接，已有候选仍在，未知输入不会自动重放。

**没有独立后台总结调用，也没有自动采纳。** 模型选择调用提案工具后，正常的工具后续回复仍可能增加一次宿主模型请求，并计入原有预算。配额限制的是候选准入，不能代替对不守工具指引的模型设置调用上限。离线适配器证明接线与错误恢复，尚未证明真实模型会选出有价值、语义准确的事件。

## 工作台实际操作验证

使用真实独立核心 HTTP、生产工作台代码及隔离演示资料，没有配置模型适配器。

- 长资料：解析 → 保存分类 → 离开/返回 → 手动刷新 → 切换人物 → 返回恢复原文与分类 → 重新解析只留一个可见草稿 → 取消预览 → 重新预览并保存 → 读回完整原文。
- 经历：原话与理由可展开；取消采纳后仍待审、时间线为空；明确采纳后只出现一条正式经历；关闭开关不删除这条经历；另一演示候选拒绝后时间线仍为空。首页显示待审数量并可直接打开候选。
- 人物核心：浏览器发现空理由晚到保存才报错，已加预览前校验和失败回归；填写理由后展示中文含义，保存并重开后核心选中，稳定策略未改变。
- 独立入口中没有真实模型预览生成按钮，续接和未连接模块不可操作；关闭入口清除人物内容并显示独立核心重开指引。

## 已知限制和后续顺序

1. 最终完整回归的 Windows 堆损坏崩溃尚未定位，不能作为“已全量通过”的合并/发布候选；需要保留故障证据，另行诊断并完成一次最终代码全量验收。
2. 真实模型的多会话人格稳定性、别称/换说法召回、事件提炼质量和实际账单未验证。固定语料评分只能检查 fixture 与评分规则，不代表模型语义质量。
3. 文档仍采用词法检索；每次操作校验获准块，没有无限期授权缓存。先用真实长历史失败样本决定是否需要向量召回。
4. 只交付第三方接入接口和 AstrBot 管理桥；AstrBot 模型注入/写入、NapCat QQ、Snow Luma 完整聊天接入未完成。DSH 原生 SDK 测试不等于完整桌面安装和生产环境验收。
5. 经历列表优先保留全部待审，最多返回 64 条（余量显示最近已处理记录）；较老已处理候选目前没有分页 UI。时间线现有快照上限 200。没有长期真实使用或百万条数据测试。
6. 增长中的事务/归档需要磁盘容量；未通过截断历史减负。故障注入不等于真实断电、硬件故障或跨系统验证。
7. 后续先做真实模型连续对话/换表述评测与显式成本观察，再决定语义检索、低频整理和完整跨宿主聊天；不在本轮提前建立空框架或后台自动化。
