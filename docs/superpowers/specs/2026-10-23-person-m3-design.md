# M3 用途、能力模块与双层约束

承接已批准 person-core 设计第 9、11 节。用户已确认系统硬约束与人物/用途规则两层均实施；单执行者串行，无后台功能。

## 边界与接口

- 用途是会话配置 `rp | companion | creation | project`，不自动创建或迁移人生线。共用人物、关系、目标、历史与人工审阅。
- 内置模块 `person-view`、`recall`、`growth-review`；固定 registry 声明协议、版本、核心兼容版本、能力、输出类别、用途及撤销行为。不加载任意代码，不暴露模型调用或真实工具执行能力。
- `memory.modules.create(authority, config)` 创建独立可用 runtime；每次 `run` 是短生命周期调用，绑定原始 authority、用途、配置、版本、调用 ID 与开始 fence。返回值的认证绑定原对象及实际内容哈希；复制或修改 JSON 不构成认证。
- 人物读取在验证视图中取数据和事件 revision；检索复用实际 retrieval receipt。操作前后检查 fence，变更或撤销则拒绝。认证证明核心读/候选操作，不证明外部行动已完成。
- `growth-review` 只能提交已有 person-growth 人工审阅候选；不能采纳、改稳定字段、构造控制凭证或把工具自述记为事实。输出/输入限额在写候选之前检查。候选使用原有可删除 payload 与依赖失效，不新增第二套事实库。
- runtime 采用同步撤销，不等待 coordinator；业务执行串行使用共享 coordinator，内部使用 raw store，避免嵌套锁。已开始的持久化可能完成为未采纳候选；撤销后不会返回成功认证，也不会提交事实。需要人工查看候选队列处理不确定结果。

## 双层约束

硬约束不可配置放宽：授权范围、固定能力白名单、无自动采纳/后台/外部执行、来源与版本校验、宿主请求总预算。用户可进一步收紧：禁用能力、保护字段 ID、限制单次检索记录数(1–32)与结果 UTF-8 字节数(1–32 KiB)。

用户规则最多 16 条，每条具有 ID 与文字(最多 512 字符)，仅作人物/用途行为指引。进入 mandatory context，不能授予权限；不宣称已实现自然语言语义冲突判定或严格遵守。结构化约束冲突返回错误，不静默截断。

## 宿主与恢复

增加 `/rp mode`、`/rp modules`、`/rp constraints`。模式、启用模块和规则变更要求空 root；禁用模块允许立即撤销并封锁有历史的旧 root，再 `continue-clean`。配置绑定放入 journal v2 可选扩展 `runtimeBinding`，同时进入每个上下文/工具快照。保存失败保持封锁，不恢复旧能力。

新会话显式创建绑定。旧 journal 不补造历史绑定；无 M3 证据的旧会话保持旧协议路径，必须干净续接后启用 M3。缺失/不匹配的 M3 证明进入 recovery-only。未知协议/版本拒绝读取；不会跳过 checksum 或从损坏 journal 继承配置。

恢复修订：用途绑定还需匹配工作区内独立 ownership marker 的 hash 与未撤销状态。变更先持久化 blocked marker，再保存 journal；marker 失败时尽力写 blocked journal，任一成功都会使冷恢复封锁。两者都无法持久化时报告 persistence_uncertain，当前进程保持撤销；不能声称磁盘完全不可写且异常退出后的状态可恢复。恢复-only 会话干净续接默认关闭模块，不继承旧启用能力。空 root 配置变更使用 generation 失效，不更改没有历史依据的 modeEpoch。

独立运行默认 RP、模块关闭。Ultra 仅沿用已认证的 `ultra-rp/v1` 排序协作；用途名 project 不启用 Ultra 工程归档或压缩。模块输出只通过显式命令展示，不自动拼入模型历史。

## 验证

测试先行：配置拒绝、能力拒绝、不可伪造回执、版本竞争、即时撤销、候选不入事实、保护字段、预算、模块关闭后核心可读。真实 SDK 离线 terminal 验证用途/规则到达请求、历史切换拒绝、禁用封锁与干净续接、冷恢复与缺证明拒绝。最终完整五命令及实际包共存验证；模型语义、任意第三方模块与长期性能另列未验证。
