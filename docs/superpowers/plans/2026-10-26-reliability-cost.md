# Memory-Continuity 可靠性与使用成本实施计划

> 执行方式：当前执行者串行实现，先复现再修复。沿用 systematic-debugging、test-driven-development、writing-plans；用户已要求简短计划后直接实施。本轮不合并、不发布。

**目标：** 控制实际模型请求次数与重复上下文，在保留必要记忆、来源、权限及分支隔离的前提下改善连续会话。

**架构：** 复用 SDK 的原生会话日志、请求准入和候选审阅。先验证真实宿主调用链，避免用内部序列化体积推断账单。整理建议以现有候选和来源认证为基础；用户已选择按需触发、重复请求复用候选。当前实现采用本地摘录，无模型调用。

**技术：** TypeScript / Node 22 / DSH rc.2、rc.3；实际 SDK 离线适配器。现有前端不重做。

## 已审查的路径

- `dispatchInput → agent.followup → preStep / systemPrompt.assemble → prepareRequest → buildRequest → llm/stream → adapter`。
- 工具结束后进入下一 step；错误完成后宿主询问 `agent/request-error`，外部恢复处理器可以继续返回 retry。
- 现有 `planContextRetirement` 在所有 enter 决策后替换旧快照，尚未区分“当前快照仍适用”和“没有消息的空步骤”。
- SDK surface 只有 append / replace；不能未经认证删除其他插件上下文或原始用户/工具历史。退役占位消息的长期开销需要实测并如实报告。

## 串行任务

1. `test/rp-cost-reliability-host.test.mjs`：用真实宿主复现不变的工具步骤重复替换、空步骤修改历史、宿主重试/工具循环没有本插件上限。离线适配器另设测试兜底上限，避免失败测试本身无限运行。
2. `src/rp/context-retention.ts`、`rp-plugin.ts`：仅在新上下文确实替换旧上下文时退役；精确正文/来源认证不放宽；保留异源片段与可追溯日志。
3. 新建独立请求限制模块，复用宿主已落盘 turn/step/attempt 事件，加准入与重试双重上限、诊断和恢复指引。验证工具循环、连续错误、正常后续输入、冷恢复、取消、持久化失败；不声称能控制第三方适配器内部 HTTP 重试。
4. 长序列离线验证：连续对话、工具调用、恢复与不同分支；记录实际适配器收到的消息、内容字节、请求数及各类占用。固定语料结果与模型语义质量、真实账单分开。
5. 按需整理与交接、召回和资料修订逐项补齐：先检查已有服务，围绕来源/去重/过期/权限/确认边界添加失败回归；不默认增加后台任务，不预设向量库。
6. 更新报告、指令及使用成本说明；串行执行类型检查、构建、全量测试、固定语料评测和打包检查。单独标明 rc.2/rc.3 的实际宿主验证、失败记录和未验证项。

## 审查重点

- 没有输入的唤醒不得凭空制造模型请求。
- 未变化的工具步骤保留当前完整记忆包，不能只剩退役占位。
- 重试限额不能被冷恢复或下一个 step 重置；下一次显式输入可获得自己的额度。
- 停止必须保留已提交工具结果，不自动重发 ambiguous 输入。
- 更正/删除后的历史认证、用户原话和兄弟分支不能因省 token 被绕过。
