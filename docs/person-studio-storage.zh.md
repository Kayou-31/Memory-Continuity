# Ultra-RP-Memory 0.2.0-dev.1：人物工作室与存储

此包独立可用；Ultra Mode 是可选兼容组合。没有任何后台自动摘要、压缩、成长采纳、轮询或付费 API。人物/经历必须有可验证来源，正式变化必须由用户明确确认。

## 打开人物工作室

在原生宿主中：

```text
/memcont start
/memcont person manage
```

打开返回的完整 `http://127.0.0.1:随机端口/#临时凭证` 地址。凭证只属于本次原生会话，不复制到聊天或日志；页面读取后从地址栏移除。服务不监听局域网，不加载外部资源。所有变更先预览，再点击确认写入；其他操作改变数据后，旧预览会被拒绝，需要刷新并重新检查。

页面提供人物档案、经历与时间线、定向关系与目标/承诺、成长审阅、用途与规则五个区域。人物创建支持身份/背景/表达/价值观/边界/性格六种初始字段；完整八种字段与情境有效期仍可用离线编辑器和可信命令。关系不自动双向，承诺暂停/完成必须显式记录；成长提案没有成为事实，直到确认采纳。时间线和经历各显示最近200条，原因选择器显示最近50条；更早数据用原有检索/命令访问，不删除历史。

“当前查看人物”仅选择页面对象。改变聊天绑定仍用空root上的 `/memcont person use <personId>`；已有历史先干净续接。用途与规则区域展示当前配置，修改使用既有 mode/modules/constraints 命令。这样可保留宿主对上下文切换的检查。

```text
/memcont person manage-close
```

关闭入口、会话销毁、人物绑定或配置变化后，旧凭证失效。已返回浏览器的文本无法远程抹除；关闭按钮及刷新失败会清空页面。提交前再次检查资格；已经发给文件系统的rename可能完成，重开后检查实际记录，使用原幂等操作恢复，不靠自动重复点击创建新事实。

## 全局存储显式升级

仅升级选中的 profile/world scope，人物分支仍使用原来的事务布局。先查看：

```text
/memcont global storage-status {"worldId":"my-world"}
/memcont global storage-enable {"worldId":"my-world"}
/memcont global storage-status {"worldId":"my-world"}
```

`{}` 表示 profile scope；可用已授权 entityId 细分世界范围。命令由可信用户执行，不是模型工具。现有权限白名单不会因此放宽。

升级前在 writer lock 内验证完整元数据链与未删除的发布正文，补齐合法未封存事务，复制并逐文件校验备份，sync后写完成manifest，最后发布升级commit。完成备份位于 `.dsh-rp/v1/backups/global/<backupId>`，状态返回备份ID与manifest SHA256。没有manifest的目录只表示失败尝试，不可作为完整备份。

| 布局 | 普通发布的完整逻辑envelope | 控制操作硬上限 | 记录/幂等键上限 |
| --- | --- | --- | --- |
| 默认 v1 | 3 MiB | 4 MiB | 4096 publications，3072发布keys/4096控制keys |
| 手动分段 | 8 MiB | 12 MiB | 8192 publications，8192发布keys/12288控制keys |

分段页最多256 KiB，每类最多128页；页按SHA256重用，原事务和幂等历史不截断。读取会校验所有被引用页、重建完整逻辑状态与整条事务链。超限返回 capacity_exceeded，原数据保持可读，同幂等键恢复不增加数据。硬上限也可能阻止新的控制事务，因此不要把12 MiB当作日常写入目标。

branch/global语义记录v1不变；分段是新物理描述符 `rp.global-segments/v1`，该scope必须由新版读取。旧程序明确拒绝读写，不能降级后继续使用该scope；新程序也拒绝升级后的格式回退。host journal仍为v2，没有自动迁移未认证工具历史。

## 恢复与限制

封存失败时可能返回 persistence_uncertain：commit已经发布。保留原始请求与幂等键，冷启动后同键恢复会先补seal，不会再发一次事实。未发布commit之前失败为 persistence_failed；损坏页或历史必须处理损坏原因，程序不会跳过哈希校验。

需要降回旧版时，先停用插件并另存整个升级后scope，再逐项核验备份manifest，恢复同一profile下该scope的完整 commits、blobs、seal.json；不要把新旧事务混合，不替换整个profile identity。此过程只在隔离测试profile实测，日常数据须另外完整备份。升级后的新数据不在升级前备份里。

备份含原始正文，在线隐私删除不会删除这些独立备份或宿主日志。分段失败可能留下未引用页，本版保留它们，不运行自动垃圾清理。

分段改进有界容量和重复写盘，不消除全历史校验成本。未验证数月连续使用、真实断电、多进程恶意写入或真实模型的长期人格语义。四类M4故事、两个对照组与实际SDK路径的准确范围见 RESULTS；不将规则分数当成模型质量。
