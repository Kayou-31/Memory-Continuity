# 下一阶段怎样判断记忆有没有帮助

这轮先把权限、诊断和工程验证补稳。固定语料与离线 SDK 已能检查“旧证据有没有漏出来”“返回记录能不能认证”，仍不能回答真实模型是否理解了人物。下面把两类证据分开，避免漂亮的 fixture 分数替代人物连续性。

## 四个场景、两个对照

所有条件读取同一份合成故事的固定修订，使用相同模型、解码参数、问题顺序、总上下文和输出预算。当前记忆组复用实际 packet/retrieval 代码，不另写一个有利于演示的检索器。两个对照为最近会话窗口、未过滤历史档案；后者只用于合成语料实验，不能成为产品恢复路径。

| 场景 | 必须观察的行为 |
| --- | --- |
| 换会话以后还是同一个人 | 身份、稳定边界与情境感受分开；不能把另一人物的经历据为己有；关系 A→B 不自动变成 B→A |
| 更正与忘却 | 新版本回答正确；旧事实、已撤回推断与隐私删除内容不能继续出现；兄弟分支按各自有效历史回答 |
| 一起走过的事与没做完的事 | 跨会话延续承诺对象、目标状态和下一步；已取消、完成与暂停不能混同；解释变化时给出有效依据 |
| 换一种说法还能想起来 | 直接用词与改换表述分别评分；保留原问/改述成对结果，检查语义召回是否比关键词不足明显 |

每个场景先冻结人工标注的事实、允许的证据片段和合理的“不知道”。答案必须同时满足事实正确、归属正确、引用支持对应断言；只在同一 source 出现过不计支持。记录错误类型及原回答，不能只保留总分。对推测、日记理解和世界事实分别标注，不能把主观理解当事实答对。

执行时顺序跑三组，交换组别顺序复测，保存实际输入、返回原文、模型版本、用量、工具回执和代码提交。没有独立真实模型结果就写未验证；当前不接付费 API。可用的本机或已授权模型执行渠道需先确认能真实传入输入并保留原回答，再开始采样，不能用脚本填好的答案冒充模型输出。

这只是128条短记录、单分支、少量样本。没有生产p95、跨平台负载、数月大文档库或多进程并发结论。报告保留全部样本，后续用同一脚本在前后提交上比较；不要为了获得好数字减少权限/哈希/版本校验。

## 根据什么决定先改哪里

- 当前已观察到历史增长时检索与准入成本同时上升。下一步先分析存储重放、重复认证与索引构建各占多少；若占主要时间，再评估按认证修订复用只读快照和增量索引。缓存键必须覆盖分支、可见范围、删除代数、来源修订及控制状态，更正或撤权后不能复用旧证明。
- 若真实模型在证据已提供时仍混淆人物/关系，优先改呈现、来源与语义约束；向量检索不能修复这种答案归属问题。
- 若直接用词成功、成对改述持续失败，且有效证据根本没被选入，再评估语义检索。仍要先授权过滤、固定结果集合、绑定实际返回版本，再评估召回率与新增成本。
- 记忆整理只在冗余明显影响成本或选择时评估，先以可审阅建议形态试验。不能后台静默采纳、改写历史或把未经验证的摘要作为可信证据。

这份记录没有宣布模型效果改进。真实模型四场景与两个对照、长期负载和进程崩溃恢复成本，仍在未验证清单中。
