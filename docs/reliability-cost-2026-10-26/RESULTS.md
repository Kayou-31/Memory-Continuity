## 从实际调用链确认的问题

审查实际安装的 DSH SDK，沿 `dispatchInput → followup → systemPrompt.assemble / preStep → prepareRequest → buildRequest → llm/stream → adapter` 追踪，再写失败回归。

| 问题 | 复现证据 | 实际改动 |
| --- | --- | --- |
| 未变化的工具步骤也退役当前记忆包 | 4 次请求的同一工具链产生 3 个额外退役占位 | 仅在完整上下文内容变化时替换；当前包继续接受原来的权限和来源校验 |
| 没有消息的步骤仍改动 surface | 被宿主取消的空步骤仍退役 1 个上下文 | 空步骤不变更记忆 surface，不凭空制造下一次上下文变化 |
| 工具循环没有 MC 层上限 | 配置上限 3 次，旧代码仍到测试兜底的第 6 次调用 | 单次明确输入请求预留上限，默认 16；达到上限后停止，保留已完成工具历史 |
| 外部重试处理器可以持续要求 retry | 配置一次重试，旧代码仍到测试兜底的第 5 次调用 | 同一步默认最多重试 2 次；准入拒绝、持久化故障不会委托其他处理器继续重试 |
| 历史校验重复读盘 | 修正后的长跑脚本第 32 轮耗时约 22.6 秒 | 一次请求内合并原文读取、批量检查历史 packet proof；不缓存跨请求的“仍然有效”结论 |
| 新增额度落盘形成异步准入窗口 | 落盘期间加入原生消息，未补二次检查时适配器仍调用 1 次 | 保存后重新核对队列、代次、owner、epoch 和取消状态；回归中适配器调用降为 0 |

单次请求额度先落盘，再进入适配器；异常情况下额度可能保守多占一次，不能根据“没看到完成回执”自动补发。冷恢复保留原计数，新的明确输入获得自己的额度。`status.requestCost` 展示限额、预留次数、步骤次数及停止原因。

## 本轮新增的整理与连续性能力

- **按需候选**：`organize summary` 从已接受的对话来源生成本地摘录，附原文范围和哈希。同一来源快照复用候选，不自动采纳。它是本地摘录整理，尚不是经过真实模型验证的语义总结。
- **轻量复核**：`organize review` 提示同角色的完全重复文本、现有投影冲突、未完成约定和久未复核的来源。不会自行合并、删除、判定过期或修改正史。
- **交接内容**：`organize handoff` 返回用户原话、当前状态、关系方向、已确认经历、未完成约定和覆盖数量。使用当前授权分支；更正后的经历及其依赖不会继续出现在交接中。不自动粘贴进模型或复制旧工具回执。
- **召回替代表述**：`rp_memory_search.queryAlternatives` 支持最多 8 个明确别称/改写，总检索词最多 128。合并命中后固定分页，无关追加不改变旧分页；返回的是实际记录及原文片段，不把检索提示写成人物事实。没有加入向量库。
- **资料修订核对**：`revisionReview` 按唯一正文或唯一标题匹配章节，提供旧分类和条件的核对建议。重复标题不猜测匹配；受众条件和启用状态不自动沿用。后端预览及独立核心 API 已提供，前端差异审阅交互尚未接入。

指令与配置示例见 [USAGE.md](USAGE.md)。`summarize-auto` 仍拒绝运行，普通聊天没有新增整理模型调用。

## 长对话实际看到了什么

脚本使用真实 DSH SDK、原生 JSONL 持久化、实际插件准入和工具执行链；最后一级是确定性的离线 `LlmAdapter`。捕获的是适配器收到的不可变请求及文字内容，**没有供应商 HTTP 请求、真实模型语义结果或账单**。

最终代码复验：64 次明确输入、72 次适配器调用，8 次工具查询；第 25 轮前冷恢复，恢复本身没有增加调用；第 41 轮前明确干净续接到同一分支。最长连续会话为 40 轮，续接后继续 24 轮。每个被发送的请求只有一个当前完整记忆包。

| 检查点 | 适配器请求对象 UTF-8 字节 | 其中 text block 字节 | 退役占位数 |
| --- | ---: | ---: | ---: |
| 第 1 轮 | 6,899 | 2,358 | 0 |
| 第 32 轮工具后 | 38,385 | 13,095 | 31 |
| 第 40 轮工具后 | 46,500 | 15,868 | 39 |
| 明确续接后的第 41 轮 | 12,455 | 4,944 | 0 |
| 第 64 轮工具后 | 30,296 | 10,342 | 23 |

表中的请求对象包含 SDK 元数据；text block 字节也不等于供应商完整序列化请求或 tokenizer 结果。两列都不能折算成实际账单。续接后的首个请求比最初第一轮更大，是因为新会话要带上当前有效的近期记忆，不能靠丢弃这些内容变小。

使用相同修正脚本的本机观察：第 32 轮耗时由约 **22.6 秒**降到最终复验的 **3.64 秒**。这里只能说明本地读盘与校验减少，没有统计置信度，也没有声明账单降低。随累计分支数据增长，第 64 轮仍约 6.77 秒；更长期的索引与存储开销仍需优化。

最后一道落盘后检查加入后，长序列已重新完整运行并通过。最终记录见 [long-final.json](evidence/long-final.json)；先前成功运行与失败边界分别保留为独立记录，没有合并计数。固定语料本轮为 12 个样本、49 个预设输出；`live.status=not-run`、真实模型样本数为 0。

## 失败、边界与未验证项

1. 最初长脚本反复确认已经接受的回复，产生无关开销；停止后保留现场，修正为只确认新回复。之后的 32 轮检查点才用于性能比较。
2. 原计划 128 轮的尝试没有完成。第 48 轮工具调用阶段逼近 32,768 保守预算，会话进入封锁；第 49 轮冷恢复后的请求因历史认证失败被拒绝。该失败未被后续分段成功覆盖，也不算 128 轮通过。
3. **占位消息和普通历史仍然增长**。SDK surface 当前只有 append/replace，未未经认证删除原话、工具结果或其他插件片段。48 轮尝试显示预算边界确实可达；目前仍需要显式 `continue-clean`。预算不足导致工具回执无法认证时，诊断可能显示通用的 `ownership_lost` 或历史校验失败，尚需更准确保留最初的工具预算原因。
4. 单次请求计数不涵盖第三方适配器内部的 HTTP 重试、其他插件自行调用模型或供应商收费规则。真实 tokenizer、缓存命中、输出及推理费用没有验证。
5. 固定语料和脚本回复不能证明真实模型的人物稳定性、事实归属、承诺延续或自然对话质量。没有为补这些分数调用付费模型。
6. 摘录不是语义归纳；重复检测是同角色精确重复，冲突来自现有投影，久未复核不是自动过期判决。没有新增自由推理式“做梦”或自动事实修正。
7. 召回替代表述需要调用者提供；无词面重叠且没有替代表述时仍可能漏召回。是否使用向量库仍待真实数据评测，不预设结论。
8. 资料修订的前端差异审阅、整理能力的工作台页面、AstrBot/HTTP 对应新入口未实施。本轮按要求暂停前端重做。rc.3 做了实际 TGZ 的关键宿主验证，未重复整组长对话；真实 QQ/NapCat/Snow Luma 收发未测试。
9. 解包曾出现 GNU tar 将 `D:` 当远程地址（退出 128）、缺少可执行 gzip（退出 2）。改用 Python 标准库并校验所有归档路径后成功；没有反复安装依赖或更改系统环境。
