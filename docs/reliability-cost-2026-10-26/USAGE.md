# 记忆留得住，调用也要算得清

这份说明对应 `fix/reliability-cost-next` 的未发布开发代码。公开版本仍是 0.3.0-preview.1；本轮没有合并、推送或发布。

## 一次输入会花在哪里

一次 `/memcont input` 可能有一次普通回复，也可能先查记忆、再根据工具结果继续回答。后者通常需要多次模型请求。模型报错时，宿主的恢复处理器还可能重试。

新增 `requestLimits` 管住的是**进入适配器前的请求预留次数**：

```yaml
requestLimits:
  maxRequestsPerInput: 16
  maxRetriesPerStep: 2
```

默认每次明确输入最多预留 16 次请求；同一个工具步骤最多 1 次初始请求和 2 次重试。可配置范围分别是 1–128 和 0–8。不是每轮固定发送 16 次，也不是插件自动发起重试；是否重试仍由宿主决定，插件负责限制上限。

次数会先写入 journal，再进入适配器。崩溃或写入结果不确定时，宁可保留一次已预留额度，也不猜测“应该没发出去”而自动补发。重新加载不会重置同一输入的计数。达到上限后先检查已完成的回复、工具结果和 `/memcont status`，需要继续时明确发送新的输入；ambiguous 输入不会自动重发。

`status.requestCost` 包含限额、当前输入 ID、请求预留次数、当前步骤次数和停止原因。它**不是账单**：其他插件可能在准入后拒绝请求，第三方适配器也可能在内部自行重试 HTTP。真实费用还取决于供应商的 tokenizer、缓存命中、输出/推理 token、失败请求计费及价格。

## 记忆不会只在第一轮出现

模型每次需要看到当前有效的人物与记忆。后续请求复用未变化的记忆上下文；内容变更时替换旧包的发送视图。工具步骤中，如果完整上下文没有改变，就继续用同一份经过认证的包。

原始用户话语、正常回复和已认证工具结果仍随宿主历史增长，不能为了省钱悄悄删掉。DSH rc.2/rc.3 的 surface 接口只提供追加和替换，旧包退役后仍留下可认证的占位消息；它们也会占用一定预算。**本轮没有让单会话无限增长，也没有开启压缩。** 到达预算边界时需要明确执行 `continue-clean`。新的会话使用同一授权分支，历史原件仍在存储里，旧工具回执不会直接复制过去。

32,768 是记忆预算上限，不是每轮发送量。未匹配受支持 tokenizer 的模型会使用 UTF-8 字节作保守计量，因此不能把该模式下的 32,768 当成精确 token，也不能把内部请求对象缩小多少换算成账单下降多少。

## 按需整理，不在聊天背后增加调用

```text
/memcont organize summary
/memcont organize summary {"sourceRevisionIds":["source_实际ID"]}
/memcont organize review
/memcont organize handoff
```

- **summary**：默认选最近 8 条已接受的对话来源，或明确选择 1–32 条。生成带来源 ID、原文范围和哈希的本地摘录候选；同一来源快照复用同一个候选。每条摘录最多 512 个 UTF-16 单位，不截断代理对，超出部分会标记并保留原文读取依据。这是本地摘录整理，**不是已经验证的模型语义总结**。
- **review**：列出完全相同的同角色文本、现有投影中的冲突、未完成约定，以及默认 90 天未复核的来源。时间较久只代表值得核对，不能据此认定事实过期。不同日期说过同一句话也可能是两段有效经历。
- **handoff**：汇集当前状态、方向关系、未完成约定、最近 24 个已确认经历及最近 8 条用户原话；也可明确选择原话来源。返回覆盖数量、来源和分支版本。它不会自动粘贴到模型、自动发起新会话或把未确认回复变成经历。更正或删除后请重新生成。

三个入口都不调用模型。候选仍需 `/memcont candidate <ID>` 检查，再用 `/memcont adopt <ID>` 或 `/memcont reject-candidate <ID>` 明确决定。只生成候选不会改变正史；自动后台任务保持关闭。

## 别称、改写和跨章查找

只读工具 `rp_memory_search` 新增可选 `queryAlternatives`：

```json
{"query":"阿澈 看星星","queryAlternatives":["林澈 观星","林澈 钥匙"],"limit":5}
```

最多 8 个替代表述，总检索词数最多 128。检索在当前授权分支内合并命中，按固定集合分页，返回实际记录的 ID、revision 和原文片段。别称和改写只是搜索提示，不会写入人物定义或证明两个称呼必然属于同一个人。

这可以复用当前对话模型已经知道的说法，不需要另外请求一次模型生成查询。尚未加入自动别称学习、embedding 或向量库；完全没有词面重叠且没有提供替代表述时，仍可能漏召回。

## 修改长人物资料

修订预览现在带 `revisionReview`。章节全文唯一匹配时标记为 `exact-text`；标题唯一匹配时标记为 `unique-title`，并提示正文是否改变。旧分类、受众条件、启用状态可以作为核对建议；重复标题和无法唯一匹配的章节进入待核对列表。

建议不会自行应用，不会把“仅私聊”改成“所有场合”。原文与新章节 ID 仍按新内容生成。后端预览和独立核心的 `reconcileDocumentRevision` API 已提供这些信息；本轮没有重做工作台，完整的可视化差异审阅和一键选择建议尚待前端接入。

## 数据兼容边界

branch/global store v1 不变。host journal 仍使用 v2，新增可选 `requestCost` 字段，严格校验并绑定已有输入。已有经过认证的 v2 journal 首次请求时会按当前输入对应的原生 attempt/message 历史保守初始化计数；缺失来源或损坏历史不会得到新额度。

旧版本的严格读取器不认识新增字段，可能拒绝读取已经由本版写入的 host journal。升级前备份整个 profile；需要降级时恢复对应备份，不手工删除计数字段来绕过检查。人物、来源和分支记录没有借这次迭代做历史迁移。

独立 TypeScript 核心也提供 `organizer` 和资料核对函数。新增整理入口当前接入 DSH 指令；AstrBot 管理桥和 HTTP 管理 API 没有在本轮增加对应交互入口，也没有验证其模型注入效果。
