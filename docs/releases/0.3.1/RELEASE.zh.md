# Memory-Continuity 0.3.1 · 值得留下的，慢慢记下来

长时间相处以后，人物不该只剩一段塞不下的简介，记忆也不该变成越积越重、说不清出处的文本。

这一版补上了从聊天到经历审阅的入口，也把长资料、读取一致性和工作台重新打磨了一遍。没有开启后台自动整理，没有替你决定哪些变化该留下。

## 聊天里的经历，可以先成为一份提议

手动启用 AI 经历候选后，AI 可以在当前聊天中提出值得记录的片段。工作台会把候选、理由和对应原话放在一起；你采纳之后，它才进入正式人生线。

这项能力默认关闭，有频率、次数和候选容量限制。候选不是已经发生的事实，开关也不是自动采纳。工具提出候选后仍可能有正常的模型后续请求，不能把它理解为免费额外总结。

## 人物资料写完整，记忆整理看清楚

- **长资料保留原文。** 在预算内检索并取出相关片段，记录人物、版本、范围和哈希；不用为了塞进一次注入而把原文删短。
- **自我核心可以明确选择。** 哪些字段需要稳定保留，由你设置；必要内容放不下时会拒绝发送并解释原因。
- **相似经历并排核对。** 在“记忆整理”主动开始本地检查，就能看到符合条件的相似线索和各自出处。否定、数值或时间不同会提醒，不自动合并。
- **导入草稿更容易找回。** 当前管理入口内保留有限的近期草稿，资料修订不必因一次关闭面板就全部重来；硬刷新或关闭管理入口后仍需重新打开。
- **人物下拉更清楚。** 用途、当前聊天、正在查看和待审阅数量各有小标签，长名字可以换行。浏览另一位人物不会悄悄切换聊天。

相似检查采用有界的本地文字算法，不调用模型。它能帮助找出值得看的记录，但还不会可靠理解所有改写或关系方向；相似分数也不是事实置信度。

## 把容易忽略的边界补牢

这一轮修复了读取参数被异步修改、撤销与读取交错、候选控制来源失效、失效候选占满容量，以及偏好保存超时后仍继续发布的问题。成长提案的保存移到一致读取视图之外，避免自己触发读取失效。

旧记忆包不会作为完整正文一轮轮堆叠发送，调用与重试继续受到上限约束。普通聊天历史、工具声明和结果、退役占位仍会增长；这些改进不等于已经证明实际账单下降。

## 升级之前，留一份能回去的备份

先停止旧写入者，备份完整 profile 与工作区。显式人物核心使用新的读取能力标记，旧 0.3 读取器会拒绝升级后的工作区；需要降级时恢复整份备份，不要删除标记绕过检查。branch/global 仍为 v1、host journal 仍为 v2，但新回执字段也有严格读取边界。

本地最新树完整回归 **484/484** 通过，固定语料、实际分包和宿主验证见[实际执行报告](RESULTS.md)。免费 DeepSeek 探测返回额度上限，Go 订阅探测返回认证失败，因此本轮没有真实模型效果成绩，也没有账单节省结论。

真实生产资料升级、断电、多日负载、完整移动端与无障碍矩阵仍未验证。后台自动摘要、自动成长采纳和单会话压缩不在这次发布中。更自由的整理建议、语义召回和更多宿主接入，会继续根据实际验证推进。
