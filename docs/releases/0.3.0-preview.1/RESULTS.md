## 发布范围

DSH 0.3.0-preview.1、独立核心 0.1.0-preview.1、AstrBot 管理桥 0.1.0-preview.1 分包交付，另附完整源码。稳定 0.2.1 保留，不覆盖 main、稳定标签或旧附件，不发布到 npm registry，不开启后台自动摘要、压缩、自动采纳或付费 API。

本轮包含完整人物原文与章节分类、共同日记、32K 预算、管理工作台、权限与恢复改进、独立核心初始化和显式 AstrBot 管理桥。AstrBot 模型注入、NapCat/Snow Luma 整链与前端视觉定稿不属于已完成范围。

## 实际请求变化

同一合成人物和三轮输入，旧候选包与新实现使用同一真实 DSH 调度及离线终端。旧包在新回归下按预期退出 1，新实现退出 0；记录在 `final/metrics-before.json` 与 `metrics-after.json`。

| 轮次 | 旧请求 UTF-8 字节 | 新请求 UTF-8 字节 | 完整记忆包份数：旧 → 新 |
| --- | ---: | ---: | --- |
| 1 | 6773 | 6593 | 1 → 1 |
| 2 | 12293 | 7200 | 2 → 1 |
| 3 | 18211 | 7997 | 3 → 1 |

这是该合成场景序列化请求的字节数，不是 token 数、真实账单或普遍节省比例。首轮额度最高 32768；后续可选内容最多 2048 当前计量单位。必需身份、边界、冲突、工具历史与包装仍计入总额，整次请求可能超过 2K。首轮也不会为了达到额度而填满。普通聊天和其他插件内容仍可能重复作为历史输入，实际费用及缓存规则取决于服务商。

## 失败记录与诊断

- 成本首批回归在旧实现失败；开发中先修正 pre-step 对真实 `payload.agent` 的使用，随后修正测试终端缺少 `index: 0` 的夹具问题。不能把夹具错误说成生产修复。
- 审阅指出当前 packet 证明、预估退休节点漏计、原文覆盖缺口，均先获得失败回归再修复。`input-coverage-red.log` 中确实出现不该到达终端的请求；修复后该请求被准入拒绝。
- 第一轮追加成本后的完整命令 **363/365、退出 1**：一条旧日记断言未适配新行为；生命周期测试子进程在依赖加载时抛出 `ERR_INVALID_URL`，9 条内部测试未启动。修正日记断言后，针对三文件的 21/21 通过；再独立执行上述完整 373/373。没有拼接结果。URL 异常未复现，根因未确定，不声明修复了 Node 或系统问题。
- 独立构建的外层记录器与内层 build 输出曾使用同名日志，导致该日志混写；退出码回执与产物比对仍完整。保留混写原件，并以独立路径补跑该干净目录的 build，退出 0，见 `independent-build-recheck.*`。不是重跑全量测试。
- 最终源码比较拦截了独立验收目录中的四个 Python 字节码缓存；补充 `.gitignore`，以不带缓存的 519 文件源码重新独立安装、构建与比对，全部命令退出 0。前一份带缓存检查点保留，发行 ZIP 只读取最终 Git 提交中的文件。
- 发布前第一次 Git push 遇到 HTTP 500；第一次 `git archive --format=zip` 生成的 ZIP 有 tokenizer 成员 CRC 错误。坏 ZIP 保留且不发布；Git 对象与工作区原文件哈希一致，`git fsck --full --no-dangling` 退出 0，但根因未确定。发行源码改从指定提交逐个读取 blob、核对 Git 对象 hash，再创建 ZIP 并逐文件/CRC 核验。
- 更早的一次 Node 0xC0000005、Git 对象故障和源映射比较器失败仍保留在阶段记录，不以本次通过倒填历史结果。公开日志会脱敏能力链接/凭据并规范化文本编码；原始诊断文件保留本机。

## GitHub CI 追加检查

第一次远端完整命令为 **363/367、退出 1**（run 40321917411，261346.1864ms），保留为失败记录：三个旧读取器文件在 GNU tar 解包时把 Windows 盘符解释为远程主机，另一个 AstrBot 打包检查因 Windows CRLF 导致版本正则无法匹配。没有跳过这些检查。

三个测试与同类基准脚本改为在目标 cwd 使用相对归档路径；AstrBot 构建器允许行尾 CRLF，仍保留打包原文字节与 manifest hash，非法版本明确拒绝。CRLF 夹具先本地失败，再在 GNU tar 1.35 下运行四个受影响文件，**10/10、5017.3526ms、退出 0**。生产 TypeScript 运行代码与上述实际包保持一致；这些构建/测试修正后的整套远端结果另存发布页 `PUBLICATION-AUDIT.json`，不把定向 10 项拼入本机全量 373 项。

CI 的同分支 push 与 PR 改用相同串行组，避免重复消耗资源。首次重复 push 检查曾显式取消，最终以当前提交的完整流水线为准。首次附件上传及草稿保持未公开，只有最终附件核验后才发布。
