# Memory-Continuity 0.3 预览 · 把人物写完整，也把今天留下来

人物不该因为一个输入框太小，就丢掉一半表达习惯；一起度过的一天，也可以有一个比聊天记录更容易翻看的地方。

这次预览带来了完整人物资料和共同日记，也把记忆预算、恢复诊断与独立运行补得更扎实。仍然是那句话：**让会话可以结束，让你塑造的人物继续。**

## 这次可以体验什么

- **放下完整的人物资料。** UTF-8 Markdown 或纯文本原文单份最多 1 MiB，章节可以分类、设置适用条件和注入资格。未知部分照样保存，不静默丢弃。原文编辑后要重新核对章节分类与条件，旧选择不会自动映射到新原文。
- **一本双方都能写的日记。** 你可以写今天的感受；在 DSH 中明确启用后，AI 可以在当前授权对话里调用专用工具写日记。作者、版本、修订和来源各自保留。没有后台自言自语，也没有自动改写人物设定。
- **给人物空间，也少发重复内容。** 首轮按需使用最高 32,768 token 的总记忆额度；后续可选记忆最多 2,048 当前计量单位，旧记忆包退出模型发送视图，原始证据照常保留。必需身份、工具历史与包装仍计入总额，这不是整请求 2K 上限。固定离线 DeepSeek V3.2 文本 tokenizer 与保守计量分别标明，实际账单仍取决于服务商。
- **改变之前看清影响。** 资料、日记、预算与设置接入工作台，浅色与深色继续沿用原外包设计；额外影响弹窗可关闭，明确保存、权限、版本校验及删除等必要确认保留。
- **出错以后有路可走。** 诊断区分绑定健康与请求准入；异常关闭先撤权，干净续接不自动重发结果不明的输入。全局容量、事务封存、来源失效与并发检索继续保留失败关闭的边界。
- **核心第一次独立分包。** 不需要 DSH，也能显式初始化一个新空间，启动本机管理服务并管理人物。AstrBot 则先提供一个小而明确的管理员管理桥。

## 开始之前

**请先备份完整 profile 和工作区，在独立 profile 体验。** branch/global store v1 与 host journal v2 保持不变，但人物原文、共同日记和新预算会建立新版读取要求。旧 0.2.1 对新增能力会拒绝读取，回退应恢复核验过的升级前备份，不能删除能力标记硬读。

DSH 包默认禁用，按 [README](../../../README.md) 完成配置再启用。独立核心的 `init` 只接受全新目录，之后仍须显式 `serve`；不会导入旧聊天或自动启动后台服务。新版官方入口对同一 profile 使用单写入者保护，切换宿主前先关闭旧实例。

## 这次还没有做完的部分

**AstrBot 当前是管理桥，还不是模型记忆适配器。** 可以由管理员私聊连接核心、查看绑定、打开工作台、关闭临时会话；人物注入、平台人物绑定和模型日记工具仍关闭。真实 provider 重试边界已有实验，但跨进程准入尚未形成可发布闭环。

NapCat、Snow Luma 的真实 QQ 整链尚未验证。工作台新增功能已有交互检查，但视觉呈现还没达到期望，按最新反馈暂停调整，之后会重新对着外包原稿讨论；这次不把它当作视觉定稿。全局发布/撤销、摘要、分支与 retcon 的完整图形操作仍待补齐，可使用已有命令。独立核心也没有完整 GUI 初始化向导或自动迁移器。

真实模型长期人格稳定性、语义召回效果、生产数据迁移、真实断电、多日压力，以及完整 DSH rc.3 桌面安装流程仍未验证。固定语料分数只代表固定记录与协议检查。

后续会继续完善安全的 AstrBot 模型接入、两种 QQ 接入、工作台功能与视觉，再依据实际效果决定语义检索、技能经验和长期整理的优先级。Ultra-Memory 仍独立；可选项目记忆协作是后续方向，本轮没有融合压缩。

详细证据见 [本预览验证报告](RESULTS.md) 与 [完整开发记录](../../framework-evolution-2026-10-25/RESULTS.md)。
