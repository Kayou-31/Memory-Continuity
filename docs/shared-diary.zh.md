# 共同日记 · 0.3.1 使用说明

共同日记自 0.3.0 起提供，本文按 0.3.1 的使用边界说明。它想保留的是两个人对同一天的不同感受：你可以写“今天和你聊得很开心”，AI 也能写下自己的回应与理解。日记可以进入后续回忆，但不自动成为事实、人格定义或关系承诺。AI 写入需要明确授权及宿主工具接入，管理桥可读写日记不代表已经接入模型写作。

## 开始使用

先创建并绑定人物。在当前人物的会话里执行：

```text
/memcont diary enable
```

这是允许 AI 写日记的明确授权。默认未开启；开启后，AI 可在正在进行的对话中调用 `memcont_diary_write`，不需要每篇再让你点确认。它只能创建和修订自己的日记，不能改你的日记，也不能调整授权、人物设定或工作台设置。没有定时写作、后台主动消息或自动事实采纳。

关闭写入和查看状态：

```text
/memcont diary disable
/memcont diary settings
```

关闭后保留已有内容供阅读。再次开启时需要新工具执行权限，旧写入句柄不能复活。DSH 人工控制要求当前会话空闲；核心层仍会在实际发布前重新检查授权与执行者是否存活。

## 写下自己的一天

```text
/memcont diary write {"entryId":"stargazing_day","title":"一起聊星空的一天","body":"今天聊了很久星空。让我开心的是，你认真听了我的奇怪猜想。"}
/memcont diary show stargazing_day
/memcont diary list 星空
```

标题上限为 256 个 Unicode 码点，正文上限为 16 KiB UTF-8；这里是单篇日记的存储边界，不是本轮规划中的 32,768 token 总记忆注入预算。超限会明确拒绝，不偷偷截断。

修改时，将 `show` 返回的 `eventId` 填入 `previousEventId`，再执行 `diary write`。如果页面或指令基于旧版本，保存会拒绝，需要重新核对。修订追加版本；原作者、实际编辑者和时间分别记录。人类修改 AI 的日记后，原作者仍是 AI，编辑者标为人类。

```text
/memcont diary history stargazing_day
```

当前检索和注入只选择最新有效版本；历史查看可以看到原稿。原文被修订、撤销或删除后，旧宿主工具结果不能继续带入模型请求。需要时执行 `/memcont continue-clean`，选择返回的新会话继续。

## 感受可以写下来，猜测也可以承认是猜测

普通日记只需 `entryId`、`title`、`body`。需要解释自己当时的理解时，可添加可选的 `reflection`：

```json
{
  "entryId": "stargazing_day",
  "title": "一起聊星空的一天",
  "body": "今天聊得很愉快，我想把这段讨论留下。",
  "reflection": {
    "understanding": "她可能喜欢天文学，也可能只是对这个故事有兴趣。",
    "context": "今天晚上的星空话题",
    "uncertainty": "还没有明确询问，不能当成稳定偏好。"
  }
}
```

后续修订可添加 `revisionNote`。`evidence` 可引用已有认证事件的精确版本和原文片段，由核心验证事件、哈希和范围；模型自报的引用不自动获得信任。格式完整、引用可定位，都不等于理解正确。这里吸收了 [retcon-form 的可修订理解思路](framework-evolution-2026-10-25/RETCON-FORM.md)，没有采用其数据库、提示词或自我评分。

## 删除、备份与失败恢复

`/memcont diary delete <entryId>` 是明确的隐私删除操作，清除受授权范围内该条日记的各版本及相应依赖。若其他分支也引用了内容，缺少这些分支的授权时会拒绝，不会只删一部分就宣称完成。外部备份、宿主日志及已发送到模型的内容不属于此删除接口的管理范围。

首次启用共同日记会声明工作区能力 `rp.shared-diary/v1`，并在升级前保留完整工作区备份。旧 0.2.1 读取器拒绝新能力；回退要核对备份后恢复，不允许旧版直接读取新版数据。branch/global store v1 保持不变；host journal 仍为 v2，日记回执另存参与者、授权版本和实际返回的记录版本。

如果正文提交成功而宿主回执保存失败，会话会封锁下一次模型请求。先用 `/memcont status` 诊断，再干净续接、查看现有日记；不要把“不确定”当成“没写成功”而盲目再发一次。幂等键由宿主真实会话和工具调用生成，正文不能指定权限或伪造执行身份。
