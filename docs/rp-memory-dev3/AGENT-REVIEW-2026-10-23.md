## 已确认并修复

1. **P2：来源沿前驱链累积。** 每次正常成长复制所有前驱来源，最终可能触及单个事件的 256 来源上限。现改为只保留本次控制及原因经历的直接来源；前驱继续进入持久化 dependencyIds，撤回、Retcon 和隐私删除沿依赖传播。新回归检查每阶段来源恒为两项，并删除仅祖先持有的来源，确认后代清除而独立新经历仍在。260 阶段实际运行结果见 RESULTS，不把结构检查当成性能证明。
2. **P2：普通旧 JSON 被误解释为成长协议。** 只检查 protocol 字段会改变旧 v1 数据含义，甚至造成依赖验证失败。现通过同一事务的 candidate_adoption marker 显式启用成长语义；store 冷读认证 marker 后给事件对象添加内部语义标记，返回事件克隆时保留标记。未标记的 v0 字样或完整同形 v1 普通 JSON 保持旧语义，不反向补标记，不修改旧历史。新增冷恢复回归和旧源码写入、新源码读取探针。

窄审确认直接来源方案保留当前前驱、分支、audience 和删除闭包检查；冷读、当前投影、packet、固定分支历史路径均能重新确认成长标记。未发现新的具体 P1/P2，不等于不存在未知缺陷。

## 检查后未采纳的疑点

- 通过普通 state key `task:goal` 绕过终止目标：既有状态键白名单已拒绝该键，缺少有效复现。
- 给旧事件事后补成长 marker：candidate_adoption 的 eventIds 必须出现在本次 batch.events，之后的 immutable/workspace derived identity 又禁止旧 ID。因此保留探针验证，不添加重复实现。
- 任意外部 JSON 序列化会丢失内部对象语义标记：当前产品路径使用经过验证的 store 重建投影。外部直接序列化事件再调用原始 reducer 不构成已验证的持久化协议，不提供此用法的兼容承诺。
