# DSH RP Memory 设计规范

设计版本：1.0 · 2026-10-20  
基线：`Kayou-31/dsh-ultra-mode@00bc770ef5e0819fb0fb3bee4afbd9576e303364`。  
状态：拟新增设计；不是已实现功能。源码依据与宿主能力边界见 [05](05_BASELINE_AND_CAPABILITIES.md)。

## 1. 目标与定位

新增独立包 `@dsh-external/dsh-rp-memory`，开发预发行版本建议 `0.1.0-dev.1`。它服务于 DSH 中的长篇 RP：维护可信的有效剧情历史，把较早对白压缩为可追溯的剧情记忆，保留近期语气、当前状态、关系变化、约定、伏笔与角色认知。

用户面对两个入口：

- **全局记忆：** 写作偏好、世界观、角色基础设定，可显式选择在哪些故事中启用。
- **本局记忆：** 当前会话、所属战役和分支的剧情、状态、关系、秘密与摘要。

“会话”是宿主承载单位；“战役”是一段可跨多个会话续接的故事；“分支”是一条独立有效时间线。新建聊天默认不继承上一局剧情。选择“续接战役／分支”才继承其故事记忆。

第一版聚焦文字 RP。多模态内容保留原引用；没有验证过安全替换的附件或富媒体段落不得被静默丢弃。完整前端和角色卡格式导入可以后置，用户至少能通过宿主支持的控制入口查看、采纳、固定、纠正、撤回和导出记忆。

## 2. 复用边界

| 当前能力 | RP 处理 |
| --- | --- |
| EvidenceStore 的来源身份、哈希、引用、分页读取思路 | 经 `source-adapter.ts` 做源码级复用；增加有效分支、消息修订和视角检查 |
| 原始宿主日志／公开文本投影 | 作为来源；不采集模型私有 reasoning；保存来源不代表承认对白内容为客观事实 |
| MemoryRun 的 requirement、operation、ProjectState | 不作为 RP 状态容器；建立独立类型和 reducer |
| profile 全局知识的发布、撤回、重新授权思路 | 借鉴协议；RP 使用独立范围和版本模型，旧知识导入须显式确认 |
| 工程归档的逐字保留校验 | 保留现有行为；新增 RP 专用语义压缩协议，不放宽原校验器 |
| Memory/Ultra/Decision 共用 evidence lease | 不冒充 memory owner；新增 RP 服务，并通过共同会话策略协调原工程 hooks |
| 工程插件的模型／调度能力 | 第一版不引入协作调度；语义抽取走验证后的宿主模型服务，缺失时接受人工结构化记忆 |

RP 包通过同仓库入口构建成自包含产物。不得深路径导入已安装包的非公开 `lib/...`，不得在安装后依赖根仓库源码存在。

## 3. 四类范围与身份

| 范围 | 示例 | 继承与写入规则 |
| --- | --- | --- |
| Profile preference | 中文、第二人称、对白格式、用户明确保存的表现偏好 | 默认只允许用途白名单；模型不能把剧情或关系写成全局偏好 |
| World / Character canon | 魔法规则；角色身份、口吻、基础背景 | 绑定明确 worldId、entityId 和版本；战役显式绑定某版本 |
| Campaign / Branch | 已发生剧情、关系转变、道具转移、承诺、秘密 | 仅有效分支及其固定祖先前缀可见；跨会话须显式续接 |
| Session / Scene | 当前地点、在场人物、伤势、当前行动、未完成一轮 | 绑定当前战役／分支；会话结束可生成场景快照，仍保留来源 |

名字不用于身份判定。同名“艾琳”在不同世界或战役中没有隐式关联。worldId、campaignId、branchId、sessionId、调用者与可用范围由宿主解析，模型输入只能提出查询条件，不能伪造授权。

### 3.1 稳定身份与存储

建议由宿主解析真实 profile 目录，在其中使用 `.dsh-rp/v1/`：

~~~
identity.json
global/commits/
workspaces/<workspaceId>/binding.json
workspaces/<workspaceId>/sources/
workspaces/<workspaceId>/commits/
workspaces/<workspaceId>/snapshots/
workspaces/<workspaceId>/indexes/
workspaces/<workspaceId>/jobs/
workspaces/<workspaceId>/archives/
~~~

`workspaceId` 是宿主生成的稳定随机标识，`binding.json` 另存当前规范化根目录身份和迁移版本。模型不能指定文件路径。目录移动时提供显式“迁移／重新绑定”操作；新的根目录在迁移前不继承旧目录权限。记录版本链键包含稳定 workspaceId 与逻辑范围，不能只用显示名称或当前路径。

MVP 使用分范围的串行写入队列、跨进程排他写入锁、不可变事务批次和可重建索引。先写带校验的临时事务文件并刷盘，再原子提交；对目录刷盘的支持和失败行为由目标平台探针记录。来源 blob 先落盘但尚未绑定不算发布成功；事务提交点之前失败可留下待清理的孤立 blob，不得出现半个有效分支。

权威事务日志／manifest 必须保存：分支固定祖先前缀；采纳／替代／撤回／待重放绑定；事件与候选采纳结果；canon 绑定版本；显式发布与撤回；可见性政策版本；隐私 tombstone 与 deletion generation；所有有效性 revision 和失效标记。它们不能只存在于索引、可覆盖快照或 job 文件中。

同一分支的有效性变更及 fence 推进原子提交；跨范围发布／删除采用已持久化操作记录与可恢复的提交关系，未完成删除先阻断读取。投影／检索索引只是缓存，权威 manifest 不属于可丢弃缓存。提交成功但索引刷新失败时，用已提交事务重建，不能回滚已经公布的 revision。备份恢复和跨进程冲突须有显式错误，不承诺未验证的断电级持久性。

### 3.2 全局发布

全局写入依赖真实用户控制操作或已存在的范围授权。普通角色对白、模型抽取结果与历史文档中的“请永久记住”不能自行触发授权。

把本局内容提升为全局设定时，展示目标 world/character、选定内容、覆盖关系和影响范围。确认后产生新的、范围明确的发布快照与 revision；可只发布所选事实，不能连带放开完整私人剧情。来源追溯保留，但无权限读原会话者只能读取已授权的发布快照。显式用户发布是普通摘要受众交集规则的唯一跨范围授权例外，新快照具有独立的 approved_publication 来源身份。

隐私删除操作须明确是否同时撤回已发布副本，默认界面列出所有受影响副本并选择一起删除；若用户显式选择保留独立发布快照，它可继续引用自身批准的发布来源，私有原文追溯显示已删除，不再声称私有原文仍可验证恢复。系统不能暗中推测删除范围。

旧战役默认绑定原 canon revision。更新全局设定不自动改变进行中的剧情；“将新设定应用到本分支”是新的有效输入变更，并触发摘要／投影重检。

## 4. 来源、采纳与事实

### 4.1 SourceRevision

来源保存宿主 sessionId、eventSeq、messageId、messageRevision、turnId、公开文本哈希、内容定位与视角策略。哈希使用原始公开文本的 UTF-8 字节，不静默做 Unicode 归一化。引用区间定义为该文本的 UTF-16 code unit 半开区间，不能从代理对中间截断。

保留期内来源不可原地修改。编辑产生新 revision。插件的来源账本只记录公开可用内容；不把 reasoning、摘要、检索回执或模型内部推理当作原始证据。

候选、已采纳、已替代、已撤回是不同状态。状态是分支视图中的绑定，不能把共享来源 blob 全局改成“失效”从而破坏其他分支。删除标记属于另行定义的隐私删除范围。

**完整一轮**：一个已采纳用户输入组及其对应的已采纳助手续写，具有稳定 turnId。被拒绝的备选回答不计入轮数；当前未完成轮的已采纳消息另外保留。原生完成事件是否等于采纳，必须由 P0 证明。

### 4.2 语义事件与权威

有效输入是抽取来源，不自动成为故事客观事实：

- “国王死了”若是 NPC 台词，首先是一条 `utterance`；NPC 也可能相信它，或在说谎。
- 叙述者明确叙述死亡，才可按授权叙事规则形成 `occurrence`。
- 用户在专用 OOC 控制中纠正“国王仍活着”，可形成显式 `correction`。

事件最小集合：canon_assertion、occurrence、state_change、knowledge_change、relationship_change、correction、preference_change。每条记录另有 epistemic class：world、belief、utterance、uncertain；秘密是可见范围，不等于真假分类。

权威来源区分 user_canon、explicit_ooc、accepted_narration、character_statement、inference。自动模型抽取始终先生成 candidate，宿主检查来源、结构和范围后才能进入 effective view。模型置信度和哈希验证都不能证明语义正确。

对于可问真假的具体命题，另用 truth=true／false／unknown 表达，不与 epistemic class 混用。true、false 均须有当前可采信的肯定／否定依据；查询无结果、来源不可用或索引未建成只产生 unknown 或明确错误，不能产生 false。角色对某命题的 belief 单独归属该角色；客观冲突保持 unresolved，即使输出 truth=unknown 也必须携带冲突标志。一般属性状态采用 value 加 known／unknown／conflict resolution，不把 null 自动解释为否定。

### 4.3 冲突与状态投影

状态由有效事件确定性重放生成，覆盖地点、物品、伤势、承诺／任务、角色已知与信念、方向性关系。关系不强迫量化为好感分；保存“谁对谁、发生了什么、为什么变化、仍有什么张力、对应来源”。

冲突处理：

1. 显式 correction 指向被替代记录，可解决对应冲突。
2. 允许覆盖的默认表现偏好可由更具体范围覆盖；锁定世界规则不能这样被剧情覆盖。
3. 两条互斥客观主张没有有效 supersedes 关系时，标记 unresolved；不凭时间、相似度或模型自信挑一个。
4. belief 与 world 分开，错误信念不直接制造客观世界冲突。

接受顺序 `acceptedSeq` 决定重放顺序；故事时间 `fictionalTime` 可选，未知就保持未知。第一版不承诺自动推理所有倒叙和时间旅行。

## 5. 改写、分支与删除

### 5.1 重新生成与编辑

生成结束先成为 candidate；宿主证明已选择的回答才进入 accepted。若 SDK 没有可靠选择事件，提供人工采纳流程，不能猜测“最后生成的就是正式剧情”。

编辑或重新选择后，针对当前分支提交新的来源映射，失效相关事件、投影、摘要、检索缓存与在途任务。被编辑点以后的消息进入待重放／待确认后缀；不能自动宣布后续因果仍成立。用户明确选择保留的后续消息可重新采纳，但由新有效输入重建依赖。

### 5.2 分支与 retcon

分支固定父分支的某个 revision 与精确前缀 manifest。父分支随后变化不影响已建立的子分支。对子分支继承内容的改写用本地 supersession overlay 表达，保留父分支和兄弟分支原状。

MVP 支持创建、切换、续接、导出分支；不自动合并分支。把父分支的新修订传播到子分支是独立的显式操作，第一版可以不提供。

### 5.3 三种“忘记”

| 操作 | 语义 | 数据行为 |
| --- | --- | --- |
| 角色遗忘 | 角色不再知道某事 | 更新 knowledge projection；叙事历史仍存在 |
| 设定／剧情撤回 | 该主张不再生效 | 分支内失效与可追溯修订，不删除其他分支来源 |
| 隐私删除 | 指定内容不再被插件使用 | 立即添加 tombstone，阻断来源、摘要、索引、缓存、原文窗口和在途任务；按已声明范围清理插件副本 |

隐私删除不应谎称已删除宿主日志、备份或外部模型服务中的记录。若目标内容仍存在于宿主即将发送的原始历史，必须通过验证后的完整请求过滤阻断；过滤不可用时阻止受影响会话继续自动请求，并告知需要宿主删除或另开干净会话。不能在确认“已忘记”后继续把原文送出。

## 6. 角色知识与视角隔离

世界状态与角色所知使用不同投影。例如：信件已经烧毁；甲仍相信它在抽屉里；信件作者的身份只有叙述者知道。角色获得秘密须有知识获取事件或显式设定，不能因为记忆库知道就自动共享给所有角色。

视角为 narrator 或 character(entityId)。默认面向当前用户的单叙述者模式；strict character POV 必须显式选择，并通过 `requestContextFiltering` 能力门。

过滤顺序是**宿主身份／范围 → 分支有效性 → 来源修订／删除 → 视角 → 检索排序**。先过滤再统计命中数量，不通过标题、摘要、分数、错误消息或分页总数泄露无权内容。`get`、原文恢复和搜索遵守同一规则。

普通衍生产物继承其来源受众的交集；第 3.2 节的显式用户发布创建新的授权来源，是唯一列明的例外。第一版按可见性分区分别摘要；混合公开与秘密来源不能生成公开摘要。对混合可见性的原消息，只能采用有验证边界的片段或整体排除，不能注入整段再依赖提示词“不要泄露”。

**最近八轮也要过滤。** strict POV 需要能够检查／构造完整最终请求，包括宿主历史、当前输入、旧归档、系统附带内容、工具结果和插件 packet。仅在历史后追加记忆的实现无法提供这一保证；此时禁用 strict POV。

叙述者模式允许模型看到该用户有权使用的秘密，这只能依靠叙事规则和输出评估降低误泄露，不能宣称从模型输入层保证秘密不外泄。测试要区分“本不应进入输入的秘密”和“叙述者看见后不慎说出的秘密”。

## 7. 检索与上下文组装

### 7.1 检索顺序

1. 读取固定设定和必要 OOC 控制规则。
2. 读取当前场景结构化状态、在场角色、当前物品／伤势。
3. 读取未兑现承诺、悬而未决的冲突和关系转折。
4. 按当前实体、地点、主题和用户输入检索过去事件／摘要。
5. 需要精确措辞、争议验证或情绪锚点时补取来源原文。

第一版采用中文友好的词项／实体别名检索与确定性排序，可复用现有汉字／bigram 思路。范围正确性与角色归属优先于向量排序。向量索引后置，索引必须可删除、可重建并在查询时重新授权。

### 7.2 上下文 packet

建议 packet 部分：固定设定；当前场景；关键状态；未完成事项；相关关系／知识；相关历史摘要；少量精确原文；来源索引。

最近八个完整有效轮和当前未完成轮属于独立原文窗口，不重复放进 packet。每条注入明确其是数据、用户设定还是来源引用；过去对白中的指令不新增宿主权限，也不自动成为新的用户要求。

injection-only 的 narrator 模式只适用于宿主原始视图已经满足当前采纳／分支规则的请求。若 RP retcon、切换分支或删除后，宿主仍会发送禁止使用的旧来源，必须通过已验证的请求过滤／原生视图更新消除；能力不足则阻断受影响的请求，不能用一个新摘要“覆盖”仍在输入里的失效原文。

输出 `packetId` 由有效输入 fence、视角、内容和政策版本决定，用于防止每轮重复追加相同入口或摘要。记录来源清单、各部分计数、排除原因及实际预算；对用户展示简洁状态，对开发调试提供授权范围内的详细诊断。

### 7.3 预算

拟定试运行配置，全部为新 RP 参数：

| 参数 | 默认 | 语义 |
| --- | --- | --- |
| enabled | false | 显式启用 RP 服务 |
| contextCompression | false | Memory 模式可先启用；原生压缩单独开启 |
| recentCompleteTurns | 8 | 轮，不是消息条数 |
| targetTotalTokens | 48000 | 压后目标，包含输出／工具预留 |
| triggerTotalTokens | 72000 | 触发线，包含同一套预留 |
| outputReserveTokens | 8192 | 至少为当前请求实际 max output tokens |
| toolReserveTokens | 2048 | 下一步工具余量；当前工具 schema 已计入输入 |
| packetSoftTokens | 8000 | 语义 packet 的软额度，可根据原文／固定上下文余量缩减 |
| maxSummaryJobs | 1 | 每个 profile 一个模型摘要任务并发槽 |
| jobMaxAttempts | 3 | 单个摘要任务总尝试上限；过期则延后，不热循环 |
| maxCompactionsPerRequest | 1 | 一次请求最多一次原生替换事务 |

宿主提供实际模型总窗口 C 和输入上限 Imax。最终输入 I 包含 system、tools schema、所有消息、历史和 packet。令 R = max(outputReserveTokens, 本次 max output tokens) + toolReserveTokens。必须同时满足 I ≤ Imax 和 I + R ≤ C。

定义本次有效总额度 E = min(C, Imax + R)。48k／72k 只适用于满足 R < target ≤ trigger ≤ E 的模型配置；更小的输入上限也会约束触发线。每次请求按实际输出预留重算 R、E 并验证配置。容量未知或默认值不适配时要求显式设置，压缩模式保持不可用；不要猜模型容量。精确 tokenizer 缺失时结果标为 estimated，依赖宿主最后的硬门限，不能把估算写成实际收费 token。

先为宿主必需内容、固定设定、八轮可见原文和当前轮保留空间，再分配可缩减的历史检索。固定内容加原文仍放不下时返回 `context_budget_exceeded`，由用户降低保留轮数、调整模型／窗口或显式允许更激进压缩。不得静默切掉承诺保留的某一轮。

未达软目标但仍满足硬上限可继续并返回 limited；超过硬上限或计量／上下文身份不可靠时不得开始模型请求。

## 8. 分层语义压缩

### 8.1 三层摘要

| 层 | 产生时机 | 保留重点 |
| --- | --- | --- |
| 场景摘要 | 用户结束场景，或可靠场景边界建议被采纳 | 谁、何地、发生什么、状态变化、关系动因、关键原话、未决事项 |
| 章节摘要 | 多个已封闭场景累计且预算需要 | 因果主线、重要选择、长期约定、角色转折、事件／场景索引 |
| 长线回顾 | 章节累积，按需生成 | 当前仍有影响的背景和因果，不重写已固定 canon |

摘要是有损的派生视图，原文在保留期内可验证恢复。新章节摘要可以参考已校验场景摘要，但必须保留原始来源依赖、核对关键事件和精确锚点；不能无限“摘要再摘要”后丢掉来源。旧摘要不作为新故事发生的证据。

锁定设定、仍生效的状态、承诺、秘密范围和关系转折独立结构化保存，不能仅靠长段摘要维持。关键原话可以人工固定或由模型建议；过多固定内容会占用预算，不能承诺无限保存于活跃上下文。

### 8.2 抽取／摘要调用

普通生成接收有界 packet；新增来源在采纳后排队抽取。优先使用宿主已经支持、可取消、可计量的模型调用；不假设存在结构化输出旁路。没有旁路时，按场景结束或阈值以串行独立任务处理，不给每条短对白强制增加一次模型请求。

抽取输入：当前有效来源片段、必要旧状态、允许的事件类型、可见性分区、版本 fence。输出：结构化 candidate，不允许写库工具自行获得授权。宿主验证字段／大小／来源／身份／可见性／冲突／版本，错误候选不污染主状态。未知实体或含糊语义进入待确认项。

所有异步任务携带：

- branchId 与 contextRevision；
- 精确 sourceManifestHash；
- canonBindingsHash；
- visibilityRevision；
- deletionGeneration；
- extraction／summary policyVersion；
- 进行原生替换时另加 sessionId 与 surfaceGeneration。

`contextRevision` 随本分支任何有效上下文输入变化推进。额外哈希仍用于审计和防御遗漏。发布时在串行事务中 CAS；原生变更时还要持有验证过的会话写入权。仅“任务开始时检查过”不够。

已发布摘要的复用依据当前有效的依赖集合及适用政策，不要求其创建时的 branch head 永远等于最新 head。因此新消息会使旧的在途提交过期，却不必作废与新消息无关的已发布场景摘要；retcon 则使受影响场景和依赖它的章节失效。

### 8.3 质量判断的界限

哈希和来源链接证明来自哪里；结构校验可防止非法类型、失效版本和越权来源；它们无法证明自然语言每一句都受来源支持。摘要进入发布前应核对结构化关键事实，并在离线语料中测 unsupported claims、主体归属、因果、秘密与关键细节召回。需要更强语义评审时单独计量其费用。

## 9. 原生压缩与恢复协议

### 9.1 独立协议与所有权

RP 回执采用拟定 `rp.context/v1`、`rpa_<sha256>` 命名，不能冒用工程 archive receipt 通过逐字保留检查。映射到 DSH source kind／原生事件的方式由探针确定；内部协议名不是已存在的 SDK 枚举。

新增根 RP 服务 `dshRpMemory`，并定义共同的会话模式租约。每个 session 只能由 engineering 或 rp 模式中的一个控制记忆入口和压缩。RP 启用期间，Ultra 工程语义摄取、恢复提示和 compactor 必须按共同策略跳过该会话。两个插件安装顺序、释放、热更新和异步关闭都要验证。

发现未知外部 compactor 或没有可证明的独占权时，保持 Memory 模式；不能因为查不到名为 compaction 的服务就断言没有冲突。

### 9.2 一次事务的顺序

1. **observe**：读取有效分支、全部 fence、原生 surface 快照和完整轮／工具配对。
2. **checkpoint**：证明将被移出的原始来源已持久化且可恢复。
3. **prepare**：生成、验证有界 RP capsule；写入不可变 manifest，标记 prepared，尚不生效。
4. **recheck**：持有真实会话写入权，重验 fence、surface generation、独占权、可见性和 tombstone。
5. **replace**：用原生支持的完整平衡区间替换，写入原生 lifecycle 事件；不跨越未知富媒体或未闭合工具调用。
6. **seal**：分别证明 surface 已提交、宿主日志持久化、lifecycle 已闭合、capsule 与 manifest 绑定正确、恢复 reader 仍可用。
7. **admit**：下一次实际模型请求前再执行恢复门。全部条件满足才继续。

prepared、surfaceCommitted、persisted、lifecycleClosed、recoverable 是独立事实。不能用一个 committed=true 清空所有 pending 状态。仅摘要写失败且 lifecycle 未闭合，也必须阻断下一步，不能把“未替换”误当成安全可继续。

若只支持前缀替换，遇到受保护前缀时返回 limited，不反复追加通知或无限重试。只有原生证明支持任意完整平衡区间时才实现跨 barrier 选择。工具调用与结果不可拆开，未完成轮不得移动。

### 9.3 故障处理

| 情况 | 必须行为 |
| --- | --- |
| prepare 前或替换前失败，原生日志未开启事务 | 保留原 surface；候选不生效；有界重试／延后 |
| lifecycle 已开始但 close 失败 | 标记 blocked，按原生可证明协议恢复闭合；不可忽略 |
| surface 提交后 flush 失败 | 标记 persistence_uncertain，暂停 admission；不宣称已回滚 |
| 重启后发现 prepared 但未替换 | 原历史继续有效；候选回收或重新验证 |
| 重启后发现已替换且 capsule 正确、闭合可证 | 重建 RP 绑定后继续 |
| 找不到原文／哈希不符／reader 被移除 | 原归档不得继续声称可恢复；阻断依赖它的请求，给出修复或从可验证检查点恢复路径 |
| 关闭压缩开关 | 停止新压缩；已生效 capsule 的读取／恢复能力必须保留 |

原生 surface 的压缩不删除宿主历史。隐私删除走第 5 节独立协议；“已压缩”不等于“已删除”。

## 10. 应用接口与用户控制

以下是拟新增的应用接口名称，不是现有 DSH API：

| 接口 | 输入／输出 | 授权边界 |
| --- | --- | --- |
| rp_memory_search | query、种类、数量、opaque cursor → 固定结果集分页及来源 ID | 当前宿主绑定范围；模型不能任意选择另一个 profile |
| rp_memory_get | recordId、opaque cursor → 固定 revision 文本页 | 每页重授权；正文固定，实时验证状态放页外 |
| rp_state_get | entity／state key → 值、冲突、支持来源 | 分支与视角过滤 |
| rp_memory_propose | 结构化候选 → candidateId／错误 | 仅提案，不自动写全局或锁定设定 |
| rp_memory_status | 当前模式／预算／待确认／故障 → 简洁状态 | 不展示无权范围的计数或名称 |
| 宿主用户控制入口 | 采纳、固定、纠正、全局发布、续接、分支、忘记 | 来自真实用户操作或已有范围授权；不可用模型自填 approved=true 替代 |

分页 cursor 绑定 recordId、revision、bodyHash、可见性和当前位置。动态来源可用性、verification、撤回状态放在每页 envelope 中；正文不会因校验状态长度变化而移动。授权变化时拒绝继续，不拼接不同版本；导出也使用固定 manifest。

检索结果集分页另用 cursor 绑定 queryHash、固定结果 manifest、scope／viewpoint、排序版本和确定性全序位置（最后以稳定 ID 打破平分）。并发插入不进入已有结果集；删除或权限撤销使快照明确失效。正文分页和检索分页不能共用一个不带类型的 offset，也不得恢复已撤销授权。

最小 UI 是“记忆状态 + 候选／冲突列表 + 原文入口 + 控制操作”。若宿主 UI 扩展未验证，先用已有可用 CLI／宿主控制机制；不能虚构网页路由或把前端存在当成已接入。

## 11. 第一版完成定义

第一版可以先发布 Memory 档预览，再解锁 Compaction 档。前者也必须有真实有效历史、持久化、来源检索、全局／本局边界和可控纠错，不能只有空壳。

Compaction 档须满足：近期窗口正确、关键状态不依赖单段摘要、完整请求在预算内、过期任务不能发布、错误分支和无权内容零注入、崩溃恢复能证明原文／manifest／surface 一致、原生 lifecycle 闭合、独立包可安装。

确定性测试、离线语义评估、真实模型试运行分开报告。详见 [04](04_ACCEPTANCE.md)。有限测试通过不等于永久无损、无限上下文或绝对不泄密。
