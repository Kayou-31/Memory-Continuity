# DSH RP Memory：Codex 开发交接包

版本：设计稿 v1.0 · 2026-10-20

基线仓库：[Kayou-31/dsh-ultra-mode](https://github.com/Kayou-31/dsh-ultra-mode/tree/00bc770ef5e0819fb0fb3bee4afbd9576e303364)

基线提交：`00bc770ef5e0819fb0fb3bee4afbd9576e303364`；Ultra 0.6.0；独立 Memory 0.1.0。

## 交付目标

在同一源码仓库中新增独立的 `@dsh-external/dsh-rp-memory` 插件，提供 RP 专用的全局设定、会话／战役记忆、角色知识状态、分支与改写处理，以及来源可追溯的有损语义压缩。宿主仍为 DSH，Codex 是开发工具。

本包是可以交给 Codex 执行的设计、接口契约与开发计划。**没有实现、编译或发布 RP 插件；没有把待验证的 DSH 能力当成现有 API；性能指标均为待测目标。**

## 建议如何交给 Codex

1. 在 `dsh-ultra-mode` 的本地开发副本中，把本目录放到 `docs/rp-memory-devkit/`。
2. 把 06 的启动提示词发给 Codex，让它从 P0 开始。实际开发环境若有更新，先核对差异，不要求回退用户已有代码。
3. Codex 完成一个阶段就更新进度文件、保存验证命令与结果，继续下一个不受阻的阶段。不要让它一次并行实现整个插件。
4. 第一版验收采用离线夹具和本地原生宿主；真实模型质量／费用测试在指定模型与预算后另行执行。

## 第一版取舍

**优先交付：** 已采纳消息的唯一有效历史；全局设定与剧情隔离；会话／分支记忆；可编辑与可追溯的状态；按视角构建上下文；稳定分页；可恢复的语义压缩。

**后续扩展：** 向量检索、多模型自动挑选、自动分支合并、多人权限协作、完整角色卡编辑器、复杂时间推理、自动导演与剧情生成。第一版不以这些扩展为前置条件。

默认一名实现者，必要时加一名只读审查者。构建和高占用测试串行执行，不设置拍脑袋的 128 MB／256 MB 进程内存上限，不让同一 OOM 或网络失败无限重试。

## 三档可交付能力

| 档位 | 必要前提 | 可对用户宣称的能力 |
| --- | --- | --- |
| Capture | 来源观察通过；自动采纳语义未证实 | 保存来源、人工采纳、查看记忆候选 |
| Memory | 有效历史、RP 存储、全请求组装验证通过 | 单会话／战役／全局记忆与上下文注入；strict POV 另需完整请求过滤能力 |
| Compaction | Memory + 原生替换／持久化／恢复／独占权全部通过 | 历史对白语义压缩、原文恢复、故障后验证再继续 |

“能注入摘要”与“宿主实际移除了旧历史”需要分别验证。若只实现前者，交付状态必须写为 Memory 档。

## 发布前要回答的五个问题

1. 重新生成但未采纳的回答，是否会污染事实或关系？
2. 旧消息编辑、回溯改写后，旧摘要是否仍在继续生效？
3. 角色不知道的秘密，是否从最近原始消息或检索工具旁路进入了模型输入？
4. 压缩中断后，是否证明原文、摘要绑定和宿主生命周期均一致？
5. 单独安装打包产物时，是否还偷偷依赖仓库或其他伴随插件？

本包要求每个问题都有明确的测试证据，不能用一句“单元测试通过”替代。
