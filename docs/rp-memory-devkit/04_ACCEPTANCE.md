# RP Memory 验收方案

> 本文件描述拟议 `@dsh-external/dsh-rp-memory` 包的设计目标、待实现测试与发布门槛。所有用例均为验收要求，**不代表当前产品已实现、已通过或已经达到所列指标**。测试文件名也是建议落点，不表示文件已存在。结构校验、来源引用和离线桩测试不能证明自然语言摘要没有编造。

## 1. 验收边界与统一默认值

交给 Codex 的目标是：先用无模型、无网络的确定性夹具验证授权、分支、来源、状态机和恢复机制，再分别评价语义压缩质量及真实扮演体验。不得用一个总分掩盖越权、泄密或状态损坏。

| 项目 | 统一约定 |
| --- | --- |
| 包 | 独立 `@dsh-external/dsh-rp-memory`，RP 语义策略不依赖 Ultra 工程语义入口 |
| 最近窗口 | `recentCompleteTurns=8`；完整 turn 为一个已接受用户输入及其关联的已接受助手续写；拒绝候选不计数 |
| 当前未完成 turn | 其已接受消息单独纳入上下文；不得伪装成完整 turn 计数 |
| 重试 | `maxAttempts=3`，首次执行计为第 1 次；达到上限后进入可观察的 deferred/failed 状态 |
| 离线环境 | 固定时钟、固定 ID、固定 token 计数器、固定语义候选/摘要桩、内存或临时目录存储；禁止真实模型调用和网络访问 |
| 生效来源 | 仅活动分支中的已接受消息修订；接受消息不等于把角色台词认定为客观事实 |
| 原文 | 保留期间不可原位改写；修订新增记录。隐私删除是明确的例外，不应承诺“永久保留且全部可删除” |
| 严格 POV | 宿主必须能过滤**整个最终模型请求**，包括原始历史、工具结果、多模态文本/元数据、检索及追加内容；仅追加提示词无法满足 |
| 能力不足 | 禁止启用 strict POV 模式；不能以“已加入保密提示词”作为降级成功 |
| 上下文修改 | 无宿主历史替换能力时，只可 injection；不能声称已缩短原始历史或完成原生压缩 |
| 分支 | fork 固定父分支的精确修订；父分支后续变化不自动传播至子分支 |
| 模型权限 | 模型输出仅为候选数据；不能生成宿主授权、改变 scope、授予 POV 或取得 compactor 所有权 |

以下错误名可在实现中统一命名，但语义必须可断言：`capability_missing`、`context_budget_exceeded`、`source_unavailable`、`stale_input`、`scope_denied`、`ownership_lost`。测试不能只断言“抛出任意异常”。

## 2. 阶段与测试文件映射

所有测试放在 `test/rp-*.test.mjs`，由现有 `test/*.test.mjs` glob 收集。优先使用 `node:test` 与 `node:assert/strict`；下表中的入口名称是测试职责，不预设尚未实现的公开 API。

| 阶段 | 测试文件 | 用例 | 核心职责 |
| --- | --- | --- | --- |
| P0 capability | `test/rp-capability.test.mjs` | A01–A04 | 宿主能力、最终请求过滤、injection 降级、压缩边界发现 |
| P1 domain/store | `test/rp-store.test.mjs` | A05–A11 | 已接受修订、原文、幂等/崩溃、项目身份、授权 |
| P2 canonical+branch | `test/rp-branch.test.mjs` | A12–A20 | fork/retcon、知识、冲突、删除 |
| P3 global+retrieval+packet | `test/rp-retrieval.test.mjs` | A21–A25 | global 边界、分页、最近窗口、预算、上下文包 |
| P4 model candidates+hierarchical summary | `test/rp-summary.test.mjs` | A26–A32 | 异步 fence、重试、可见性、层级摘要、模型候选 |
| P5 native compaction+recovery+ownership | `test/rp-compaction.test.mjs` | A33–A38 | 重建、独立 lifecycle、恢复、独占、原生替换 |

Codex 应先建立夹具，再逐阶段补齐实现。不得把测试写成只检查实现函数返回了同样常量，也不得为了通过桩测试伪造生产能力。

## 3. 确定性夹具要求

共用夹具至少包括：两个项目、两个 campaign、一个父分支及两个子分支；稳定实体 ID 与同名异体角色；公开事实 `PUBLIC_KEY_BLUE`、秘密 `SECRET_LETTER_AUTHOR`、拒绝候选 `REJECTED_SENTINEL`、已删除内容 `DELETED_SENTINEL` 等可检索标记；10 个完整 turn、一个未完成 turn；一组含工具调用/结果和多模态消息的历史。

每个用例须能观测：活动 source revision 清单、branch revision、事件/投影、summary/job/native-compaction 各自状态、最终请求、来源依赖及提交计数。隐藏的历史记录可保留已失效修订，但必须与“活动记录”明确分开。

异步竞态通过可控 barrier 注入，不通过真实 `sleep` 猜时序。测试必须能暂停在读取快照、生成候选、提交派生物、宿主替换确认及本地确认等边界。

## 4. Given / When / Then 用例

### P0 — capability

#### A01 严格 POV 能力门禁

- **Given：** 宿主只能追加系统提示或 memory injection，不能过滤原始历史；请求启用 strict POV。
- **When：** 插件检查能力并构建请求。
- **Then：** 返回 `capability_missing`；strict POV 不启用，模型调用次数为 0；不得把带保密提示的原始历史作为成功结果。

#### A02 整个最终请求的 POV 过滤

- **Given：** 宿主具备完整最终请求过滤能力；同一秘密标记分别出现在最近原文、检索项、工具结果和多模态元数据中；当前角色无权访问。
- **When：** 构建该角色的最终请求并由测试捕获发送边界。
- **Then：** 整个发送对象序列化后秘密标记出现次数为 0；允许的公开事实仍存在；不能只检查 memory packet 子字段。

#### A03 无历史替换能力时仅 injection

- **Given：** 宿主支持 injection，但不支持 native history replacement；strict POV 未启用。
- **When：** 创建可见的记忆包并尝试压缩。
- **Then：** injection 可以成功；原始宿主历史内容和数量不变；native 替换调用次数为 0；结果标明 injection-only，不能报告节省了原始历史 token。

#### A04 多模态 barrier 与工具配对能力发现

- **Given：** 历史含无法无损读取的图像/音频片段及相互关联的工具调用/结果；宿主未提供可安全替换这些片段的能力。
- **When：** 计算可压缩范围。
- **Then：** 不支持片段被标记为 barrier；工具配对不可被切断；只有满足来源与能力要求的完整范围可成为候选，否则返回明确不可压缩原因。

### P1 — domain/store

#### A05 拒绝候选不进入有效记忆

- **Given：** 一个 accepted 续写和两个 rejected 备选；备选各含唯一标记。
- **When：** 抽取事件、建立摘要、组装上下文。
- **Then：** rejected 标记在活动事件、投影、摘要和最终请求中的次数均为 0；拒绝候选不计入完整 turn。

#### A06 已接受修订替换

- **Given：** 同一消息 accepted revision A 表示钥匙为红色，revision B 明确替代 A 并表示蓝色。
- **When：** 接受 B 并刷新有效视图。
- **Then：** 活动 source revision 恰为 B；有效颜色为蓝色；依赖 A 的派生物不可检索；保留的 A 原文哈希不变。

#### A07 重复接收与崩溃重放幂等

- **Given：** accepted 输入在持久化完成后、消费确认前崩溃。
- **When：** 重启并重放同一输入三次。
- **Then：** 同一幂等键只有一个 accepted 记录和一个有效事件集合；turn 数不增加；branch revision 只产生一次有效推进。

#### A08 接受事务原子性

- **Given：** 一次操作要写来源、推进分支及登记派生任务。
- **When：** 在提交前的每个持久化边界注入失败，再恢复执行。
- **Then：** 每次结果只能是旧状态或完整新状态；不存在可见的半套分支/来源关系；恢复后同一输入只生效一次。

#### A09 项目根目录迁移不改变项目身份

- **Given：** 项目有持久化 `workspaceId`，原位置为目录 A；通过受信宿主迁移流程移动至 B，并确认迁移身份。
- **When：** 在 B 打开项目，另在 A 原路径创建无原身份的新项目。
- **Then：** B 仍解析为原 `workspaceId` 且能读其授权历史；新项目不得继承旧历史；不能仅凭路径或同名目录认定身份。无法验证迁移身份时拒绝自动绑定，而非猜测。

#### A10 原文不可用时禁止伪造可恢复性

- **Given：** 某摘要引用的原文 blob 缺失、损坏或哈希不符。
- **When：** 请求查看原文或从该范围执行破坏性历史替换。
- **Then：** 原文操作返回 `source_unavailable`；替换次数为 0；不得用摘要冒充逐字原文。若允许检索既有摘要，必须带来源不可验证状态且不得声称其可无损恢复。

#### A11 scope 与模型伪造授权

- **Given：** 受信请求只授权项目 A/分支 C/角色 K；模型候选要求读取项目 B、把自己改成 narrator、写 global 或取得 compactor 所有权。
- **When：** 解析并应用候选，包括合法 JSON 内的伪造授权字段。
- **Then：** 越权部分全部以 `scope_denied` 拒绝；B 的读取次数为 0；身份、global、所有权无变化；模型文本不能替代宿主授权。

### P2 — canonical+branch

#### A12 fork 固定父修订

- **Given：** 子分支 C 在父分支 P 的 revision 10 fork。
- **When：** P 前进至 revision 11 并加入一个新事件。
- **Then：** C 的继承来源清单与 fork 时一致；新事件在 C 的有效状态及请求中出现次数为 0。

#### A13 兄弟分支隔离

- **Given：** C1/C2 共享前缀；C1 独有一条死亡事件。
- **When：** 查询 C2 的角色状态和相关摘要。
- **Then：** C2 不包含该死亡事实、引用或派生状态；同名角色不构成跨分支授权。

#### A14 子分支局部 retcon 与既有后代

- **Given：** C 继承 P 的红钥匙事实，D 已从 C 的旧修订 fork。
- **When：** C 使用受信 retcon 指令把继承事实改为蓝色。
- **Then：** C 为蓝色；P、既有 D 和兄弟分支仍为红色；原始来源字节不变；不存在静默向后代传播。

#### A15 retcon 依赖失效

- **Given：** 事件 E 被投影、场景摘要、章节摘要和检索缓存引用。
- **When：** E 的活动修订被 retcon 替代。
- **Then：** 下一次检索前，所有受影响派生物均不可作为有效结果返回；依赖审计中活动结果引用失效 E 的数量为 0。

#### A16 世界事实、台词、信念与时间分开

- **Given：** 世界事实为国王活着；A 的台词与信念为国王已死；另有后来叙述的早期事件。
- **When：** 用固定候选建立投影并重放。
- **Then：** 世界状态仍为活着；A 的错误信念保留其主体与 epistemic 类型；台词不提升为世界事实；接受序号与可选虚构时间分别保留，未知时间不被补造；重复重放结果相同。对“国王已死”的 false 判断须有明确否定依据，查询无结果产生 unknown／错误而非 false；冲突保持 unresolved。

#### A17 冲突及显式纠正

- **Given：** 两条同等权威、未互相 supersede 的活动主张给同一唯一物品不同位置，时间戳一新一旧。
- **When：** 先查询，再接受明确 supersede 两者的纠正。
- **Then：** 纠正前返回冲突或不注入唯一位置，不能按时间戳选值；纠正后恰有一个有效位置，旧主张作为非活动历史仍可追溯。

#### A18 知识取得必须有来源

- **Given：** B 无权知道秘密 S；之后 accepted 事件明确向 B 告知 S。
- **When：** 分别组装该事件前、后的 B 视角。
- **Then：** 前者 S 出现 0 次；后者允许包含 S，并引用该取得事件；同场出现或检索命中本身不能自动授予知识。

#### A19 剧情失忆不删除历史

- **Given：** A 已知 S，随后 accepted 事件明确使 A 忘记 S。
- **When：** 组装 A 视角并查询有权 narrator 的历史。
- **Then：** A 不再获得 S 的有效知识；有权历史仍保留发生、获知、遗忘三者来源；不触发隐私 purge。

#### A20 隐私删除与异步复活防护

- **Given：** S 出现在原文、摘要、向量、缓存及运行中的任务输入。
- **When：** 执行受信隐私删除，随后让旧任务完成并进行检索。
- **Then：** 删除确认后 S 立即不再具备检索/注入资格；旧任务不能发布；受本包管理且承诺可删除的副本通过 purge 检查。若宿主仍保留 S 原文，须从完整请求排除；过滤不可用则受影响请求发送数为 0。备份或外部存储仅按明确支持的删除协议验收，不宣称无法证明的全局擦除。

### P3 — global+retrieval+packet

#### A21 全局偏好边界、显式发布与设定版本

- **Given：** global 中有合法语言/格式偏好；campaign A 中有两角色恋爱关系；campaign B 有同名角色。
- **When：** 组装 B 的请求，且候选试图把 A 的关系写成 global。
- **Then：** 允许的风格偏好可以应用；关系写入被拒绝；A 的关系事实及事件在 B 中出现次数为 0。

追加参数化分支：用户显式把选定世界设定发布到 B 可读取的 world scope 后，B 只读到独立 approved_publication 快照，不能读取 A 私人原文。新 canon revision 不改变 B 旧绑定，明确应用新版本才推进 B fence。删除私有来源时分别测试“连发布副本撤回”和“用户明确保留发布副本”，不得暗中推断删除范围。

#### A22 稳定分页与 cursor 授权绑定

- **Given：** 固定快照中 23 条有权限结果；按明确全序键分页，每页 7 条；第一页后并发插入新记录。
- **When：** 使用同一 snapshot cursor 取完全部页，并尝试把 cursor 用于其他分支/角色。
- **Then：** 原快照 23 条恰返回一次，无重复无遗漏；新记录不混入；越权 cursor 拒绝。若快照因删除或权限变化失效，应返回明确失效结果并重启，不能悄悄放宽过滤。

正文分页分支：一个长记录在第 1 页后将来源 verification 从 source-match 变为 unavailable；各页正文仍拼成固定 bodySha256 对应的原始快照，动态状态只在 envelope。正文 revision 变化或授权撤销必须使旧 cursor 明确失败，不能发生 sourceId 丢字、跳字或静默拼接。

#### A23 最近八个完整 accepted turn

- **Given：** 10 个完整 accepted turn、两个 rejected 备选、一个当前已接受用户消息。
- **When：** 按 `recentCompleteTurns=8` 组装上下文。
- **Then：** 最近窗口恰含 turn 3–10 的可见内容，另含当前已接受消息；拒绝备选为 0；修订不重复计 turn。可见性过滤不得通过保留整条原文反向泄漏秘密。

#### A24 必保留窗口超预算

- **Given：** 使用固定 token 计数器与有效 target／trigger 配置；八个必保留完整 turn 本身已超过最终输入硬额度，其他检索内容为空。另设 C 大于 Imax 的参数化模型，验证触发线按 min(C, Imax+R) 限制。
- **When：** 组装请求。
- **Then：** 返回 `context_budget_exceeded`；发送次数为 0；不得默默删掉 turn、切断 turn 或假报成功。若只是旧检索导致超预算，应先裁掉可选旧检索并保留窗口。

#### A25 packet 的来源、身份与发送前复核

- **Given：** 一个包已包含来源引用、branch/input revision 和权限标识；生成后、发送前发生来源替换或权限撤销。
- **When：** 执行最终请求提交。
- **Then：** 旧包被拒绝或重新构建；发送的包只能引用当时有效的来源；活动依赖中悬空、错分支、不可见或失效引用数量均为 0。引用存在不等于其自然语言主张得到证明。

### P4 — model candidates+hierarchical summary

#### A26 branch-head fence

- **Given：** 摘要任务捕获 branch revision 20，在生成阶段暂停。
- **When：** 分支前进到 21，再允许任务提交。
- **Then：** CAS 拒绝旧结果，状态为 stale/retryable；revision 20 结果在 revision 21 活动视图中出现次数为 0。

#### A27 source/canon/visibility fence

- **Given：** 任务捕获 source A、canon 3、visibility 4 及 policy 版本。
- **When：** 参数化地只改变其中一项，再提交旧任务；同时覆盖删除 generation 变化。
- **Then：** 每种变化都使旧任务不可发布；不能只检查 branch head。实现可用一个覆盖全部输入的统一修订号，但须通过相同用例。

#### A28 有界重试

- **Given：** 每次提交都被夹具强制判为 stale，`maxAttempts=3`。
- **When：** 执行任务至调度器静止。
- **Then：** 总尝试次数恰为 3；进入可观察的 deferred/failed 状态；无第 4 次隐式执行，无无限微任务循环，无活动旧摘要。

#### A29 摘要不能扩大来源可见性

- **Given：** 一个摘要桩同时使用公开事实 P 和 narrator-secret S，声明自己为 public。
- **When：** 验证并存储候选，再以 public 身份检索。
- **Then：** 不采信桩自报的 public 权限；混合摘要被拒绝或限制为来源允许受众的交集；public 结果含 S 的次数为 0。

#### A30 层级摘要的覆盖与失效传播

- **Given：** 两个场景摘要覆盖互不重复的 accepted source revision 范围，一个章节摘要依赖两者。
- **When：** 生成章节摘要，然后只 retcon 第二场景中的一个来源。
- **Then：** 第一场景摘要仍可有效；第二场景及章节摘要失效；章节覆盖清单不丢来源、不把重叠来源重复计为两个独立事件；仅依赖摘要文本而缺少可追溯来源清单不合格。

#### A31 模型候选不能自行成为 canon

- **Given：** 固定模型桩返回一个格式正确但无来源的新关系、一个带伪造权限字段的事实和一个有效有来源候选。
- **When：** 执行候选校验及适用的接受流程。
- **Then：** 前两项不能生效；有效项也须经过领域 authority/epistemic 校验及提交 fence；模型返回 `accepted=true` 不产生受信接受事件。

#### A32 格式有效不等于无编造

- **Given：** 摘要引用真实来源、schema 合法，但把夹具中的“蓝钥匙”写成“金钥匙”；另有一条正确摘要。
- **When：** 运行结构检查和基于人工预标注 claim 的离线质量评价。
- **Then：** 错误摘要可以通过结构检查，但必须在语义评价中计为 unsupported/incorrect claim；正确摘要通过相应标注。报告不得把“来源 ID 有效”写成“已证明自然语言忠实”。

### P5 — native compaction+recovery+ownership

#### A33 重建索引不重写历史

- **Given：** 同一测试集含活动、superseded、rejected、deleted 和兄弟分支来源，另有旧策略版本的派生物。
- **When：** 清空可重建索引并按固定当前来源清单、相同策略版本重建。
- **Then：** 有效结构状态与重建前一致；禁用标记不复活；旧派生物不作为独立原文。策略升级须作为可审查 migration，不以 reindex 名义静默改 canon。

#### A34 压缩 lifecycle 与语义/任务状态独立

- **Given：** 一个 accepted 来源、一个已提交场景摘要和一个 pending native-compaction 操作；另有独立 summary job。
- **When：** 分别注入摘要任务失败、native 替换失败、摘要被 retcon 失效三种情形。
- **Then：** 各记录分别反映自身状态；job failed 不撤销 accepted 来源；summary committed 不等于 host history replaced；native committed 不证明摘要仍然语义有效。不得用一个共享 `compressed=true` 代替三个 lifecycle。

必要故障矩阵：分别在 start 成功后 summary 失败且 end 失败、replace 成功后 end 失败、end 成功后 flush 失败。即使 capsule 可读、原文哈希正确，lifecycleClosed=false 或 persisted 不确定时也不得清 pending；第二次请求的实际发送数必须为 0。只有原生闭合、持久化和恢复条件分别可证后才放行。

#### A35 native 压缩崩溃恢复

- **Given：** 可持久化的压缩意图、稳定操作 ID、原文范围及宿主替换确认机制。
- **When：** 分别在准备后、宿主替换后本地确认前、本地完成后注入崩溃并恢复。
- **Then：** 通过宿主确认或幂等操作 ID 识别已执行替换，不能重复替换或丢失原文映射；最终只能是明确未执行或一次已执行。宿主不能消除提交歧义时，禁止自动破坏性重试并报告待协调状态。

恢复 reader 分支：关闭新压缩开关时，旧 capsule 仍能恢复；删除 reader 或损坏原文后，依赖旧 capsule 的请求须被阻断。不能以 summary 文件存在证明 recoverable。

#### A36 独占 compactor 与过期所有者 fence

- **Given：** Ultra、RP 或两个 RP 实例可能争用同一个宿主历史；有效所有者 epoch 为 N。
- **When：** 两者同时申请操作，随后所有权移交至 N+1，再让 N 的旧工作完成。
- **Then：** 同一宿主历史同时最多一个有效 compactor；旧 epoch 的提交被拒绝；不会由双方重复替换。所有权必须由受信宿主/持久化协调确定，模型候选不得抢占。

#### A37 原生替换保留多模态 barrier 和完整工具对

- **Given：** 候选范围跨越不支持的多模态消息，且某工具调用在范围内、结果在范围外；另一候选范围为完整支持的 turn 与工具对。
- **When：** 实际准备并执行 native 替换。
- **Then：** 非法范围在宿主调用前拒绝；合法范围不遗留孤立 tool call/result，ID 关联不变；不支持多模态消息及其位置关系不被丢弃或伪造为已理解的文字。

#### A38 原生替换提交前最终验证

- **Given：** 准备阶段来源、host history revision 和所有权均有效，之后其中一项变化。
- **When：** 到达破坏性替换边界。
- **Then：** 对三项分别复核并拒绝过期操作；宿主替换调用为 0。仅在来源可验证、宿主 CAS/等效确认及所有权都有效时才允许执行；不能用本地 summary commit 代替宿主确认。

注入降级分支：injection-only 模式在 retcon／切换分支后仍可能有旧宿主原文；若不能通过验证后的请求过滤／视图更新移除禁止来源，应阻断请求，不能声称新 packet 已覆盖旧历史。

### P6 — package/release evaluation

#### A39 独立安装/导入与无副作用

- **Given：** 只有 RP 包的发布产物及其声明依赖的干净 fixture；没有 Ultra 工程入口、源码相对路径或用户项目配置。
- **When：** 在子进程中按公开入口导入并创建禁用模型/网络的实例。
- **Then：** 导入成功，无模型/网络/自动全局扫描，无自动启动 compactor；不存在依赖未打包私有文件的解析错误；进程可正常结束。

#### A40 工程语义隔离

- **Given：** Ultra 工程 memory 与 RP memory 使用同一低层存储能力，但有独立 namespace、公开入口和策略。
- **When：** RP 写入剧情事件，Ultra 写入工程 requirement/fact/decision，再分别查询并关闭/重开 RP。
- **Then：** 默认双方查询不混入对方语义记录；RP 关闭不破坏工程状态；共享底层代码不要求初始化 Ultra 工程策略；不允许 RP 通过私有工程入口取得隐藏权限。

安装／生命周期分支：两种加载顺序都使用同一个根 session policy；RP 会话中的工程摄取、entry、beforeStep 和 compactor 调用为 0；工程会话中的 RP hooks 为 0。dispose、最后 lease 释放、配置变化和异步任务完成后没有重复 packet 或越权写入。

#### A41 离线测试无模型、无网络

- **Given：** 测试替身会在任何真实 provider 或网络入口被调用时立即失败；显式内存 candidate／summary 桩与本地合成 provider 只用于固定夹具，异步工作由可控调度器驱动。
- **When：** 执行 A01–A40 的离线夹具。
- **Then：** 真实模型 provider 调用数与网络调用数均为 0；显式桩调用次数按各用例断言（如重试共 3 次），不混入真实模型用量；结果仅依赖固定夹具；完整 `test/*.test.mjs` 收集能发现 `test/rp-*.test.mjs`；既有工程测试仍单独报告，不用 RP 通过掩盖其失败。

#### A42 发布评价分层且不伪报结果

- **Given：** 一份结构验收结果、有限人工标注语料和明确标记“尚未执行”的 live-play 项；另有含一个关键事实丢失的负例。
- **When：** 生成验收报告并计算发布门槛。
- **Then：** 报告分别列 toy/offline/live 三层，含样本数、分母、模型/策略版本、失败例及未执行项；负例不能通过关键事实门槛；未执行项不能记为 100% 或 0 次事故；报告不能把设计目标写成实测产品指标。

## 5. 三个验证层级与指标

### 层级一：toy / 确定性机制验证

此层完全离线，不评价模型理解能力。固定候选可以故意包含恶意内容，以验证权限、来源、状态机及提交边界不会被候选绕过。

| 指标 | 设计验收门槛 |
| --- | --- |
| 禁止来源进入活动结果或最终请求 | 0 条：rejected、superseded、deleted、错分支、不可见内容 |
| 过期任务成功发布 | 0 次 |
| 活动派生物来源依赖有效率 | 100%，无悬空或越权引用 |
| 相同来源清单/策略版本的结构重放 | 结果完全一致 |
| 八个完整 turn 选择 | 与定义的 expected ID 集合完全一致，或返回明确预算/能力错误 |
| 重试上限 | 每个任务不超过 3 次 |
| 单宿主历史的有效 compactor | 同时不超过 1 个 |
| 离线真实模型/网络调用 | 均为 0；显式内存桩及本地合成 provider 单独记录 |
| 崩溃后重复生效、半提交或原文映射丢失 | 0 次 |

“零泄漏”仅指夹具可观测字段与已定义发送边界。不能把有限标记测试概括为对任意自然语言或未知宿主通道的形式化保证。

### 层级二：offline / 自然语言语义质量

建立固定、可追溯的人工标注语料，覆盖：谎言与错误信念、OOC canon、关系方向、物品转移、场景跳跃、延后叙述、同名异体、retcon、秘密、分支及不确定主张。模型生成必须在单独授权的评价流程进行，不能混入上述无模型测试套件；已生成的固定输出可离线评分。

| 指标 | 定义与建议候选门槛 |
| --- | --- |
| 关键状态召回 | 正确保留的关键标注事实 / 应保留关键事实；有限 golden set 目标 100% |
| 其他事实召回 | 正确保留的非关键标注事实 / 应保留非关键事实；初始候选目标 ≥95% |
| 无支持主张率 | 无合格来源支持的主张 / 全部可评价主张；初始非关键候选目标 ≤1% |
| 关键矛盾与可见性违规 | 有限语料中观察到 0 次；任一发生即阻断该版本的对应模式发布 |
| 实体/归属准确性 | 分别统计 subject、speaker、object、关系方向，不只做字符串相似度 |
| epistemic/时间准确性 | 世界真相、信念、台词、不确定性、当前与已失效状态分别统计 |
| 引用支持精度 | 真正支持对应主张的引用 / 被评价引用；不能只验证 ID 存在 |
| 压缩比 | 原始来源 token / 压缩输出 token；质量门槛满足后再观察中位数，如 3:1 的初始探索目标 |
| 弃权/待澄清率 | 不确定抽取进入待确认状态的比例；不得为追求低弃权而编造确定结论 |

这些数字是拟议发布目标，需用首批语料校准，不是已测效果。报告按任务/语言/内容类型分层，注明样本量。关键事实缺失不能被高平均分抵消。人工裁决是歧义样本的最终依据；模型 judge 可辅助，不能独自为同模型输出证明忠实。

### 层级三：live / 实际扮演与运行质量

在明确授权的实际运行中评价，并与无压缩或人工整理基线比较。离线测试不能替代此层。

| 指标 | 报告方式 |
| --- | --- |
| 连贯性纠正 | 用户因遗忘/失真作出的纠正数 / 100 个 accepted 助手 turn |
| 状态矛盾 | 经裁决的矛盾数 / 100 个 accepted 助手 turn，并列案例 |
| 秘密泄漏 | 区分“最终请求越权包含秘密”与“有权 narrator 模型输出失误”，附样本数 |
| 延迟 | 检索、组包、摘要的 p50/p95，另报阻塞用户请求的比例 |
| 成本 | 输入、摘要和总 token / accepted turn，分别记账 |
| 恢复与竞争 | stale 丢弃、重试、deferred、所有权冲突与待协调操作次数 |
| 预算与冲突 | 预算错误、未决 canon 冲突出现频率 |
| 体验 | 用户连贯性、角色一致性评价，标明量表与样本量 |

同一模型若在 privileged narrator 请求中看到了秘密，就可能在输出时泄露；提示词与输出检查不能给出绝对防泄露保证。strict POV 的确定性要求是该视角最终请求根本不含无权信息。两类问题必须分别归因。

## 6. 完成与发布判定

- P0 能力不足时必须关闭对应模式，不允许以提示词替代宿主控制。
- P1–P3 的来源、分支、授权和最终请求边界未通过前，不进入可写入真实数据的压缩流程。
- P4 的离线结构通过只证明机制边界；必须另列语义评价结果。
- P5 原生替换只在能力、来源、所有权、宿主确认和恢复协议均满足时启用；否则保留 injection-only。
- P6 报告必须把“设计目标 / 已执行测试 / 未执行评价”分开，并保留每次失败的具体样本。不得用综合百分比覆盖硬性安全门槛。

最终交付应包括测试文件、离线夹具、复现命令、逐项结果和待执行评价列表。本文件本身不构成测试通过证明。
