# Memory-Continuity · AstrBot 管理桥

这是一个可独立安装的**开发版管理桥**。它连接同一电脑上的 Memory-Continuity 核心，让管理员从 AstrBot 显式打开人物工作台、查看连接状态、关闭临时管理会话。不需要安装或启动 DSH。

当前尚未开放模型记忆注入、模型检索工具、AI 日记写入、平台人物绑定或干净续接。安装这个桥不会让 AstrBot 自动记住人物，也没有开启后台摘要、压缩、主动聊天或模型调用。请不要把“管理桥可用”理解成完整 AstrBot / NapCat / Snow Luma 兼容。

## 安装与连接

运行要求：AstrBot **4.29.3**、Python 3.12+；独立核心需要 Node.js 22+。核心 TGZ 与此插件 ZIP 分开安装，ZIP 内不捆绑 DSH、AstrBot、Node、账户资料或模型密钥。

1. 在隔离测试 profile 中准备核心配置，使用 `memcont-core serve --config <绝对路径> --connection <新的连接文件绝对路径>` 显式启动核心。核心目前要求已存在并经授权的工作区和分支，初始化向导仍待补齐。
2. 通过 AstrBot 的本地插件安装入口安装 ZIP。插件默认关闭；设置中启用管理桥，并填写核心连接文件的绝对路径。连接文件包含管理凭据，应放在账户专用目录，不要发给别人或加入 Git。
3. 以 **AstrBot 管理员身份私聊**发送 `/memcont connect`。这一步才连接核心，不会自动创建人物或导入聊天记录。
4. `/memcont status` 查看核心中已配置的绑定，再用 `/memcont open <绑定ID>` 打开对应工作台。

| 指令 | 做什么 |
| --- | --- |
| `/memcont connect` | 显式连接当前配置文件对应的核心实例；重新连接会先关闭本桥旧会话 |
| `/memcont status` | 查看连接与可用绑定；明确显示模型注入尚未开放 |
| `/memcont open <绑定ID>` | 创建短期管理会话，返回本机工作台地址 |
| `/memcont close` | 断开本桥，并尝试撤销它创建的管理会话；不关闭独立核心进程 |

工作台地址只能在**运行核心的那台电脑**上打开，含临时管理凭据，最长十分钟有效。它不会发到群聊。非管理员或非私聊的请求在读取连接文件前被拒绝，命令不会继续进入普通模型请求。工作台保存仍需原有的预览、权限与版本检查。

## 断线和恢复

连接文件更换或传输失败后，旧客户端不会自行复活，也不会自动重连、续期或重发操作。先在本机检查核心服务和所有权状态，必要时按核心 README 显式恢复，再由管理员重新 `/memcont connect`。

如果核心不可达，本桥无法保证远端撤销已经完成；本地资格先关闭，服务端仍执行短期会话限制。不要用删除锁、修改 journal 或恢复旧连接文件的方法绕过诊断。已保存但结果不明的修改应先在工作台核对。

核心繁忙而拒绝撤销时，本桥保留待清理记录，并在之后明确关闭或卸载时继续尝试；没有后台重试。待清理记录也占用本桥 16 个会话限额。正常到期后再次 `open` 会先向同一个核心确认旧会话已消失，再创建新会话，不要求重复发送命令。

## 已验证与待完成

- Python 薄客户端连接实际 Node 核心进程，验证受限检索、跨会话回执拒绝、更正后的旧结果失效、撤销、连接文件替换和断线后的资格退休。
- 使用实际 AstrBot 4.29.3 的插件加载器、配置系统、事件对象，以及从命令处理、结果装饰到发送的真实调度链，验证管理员私聊、工作台、到期重开及卸载撤销。只有最终消息终端替换为本地记录器，没有平台账户或真实 QQ 发信；这是宿主组件集成验证。
- 完整 AstrBot 启停、每次 provider 请求的准入、真实 QQ 收发、NapCat 与 Snow Luma 整链、后台长时间稳定性仍未验证。默认 provider 的内部重试、工具循环和 fallback 需要进一步接线，当前没有通过修改宿主源码绕过这些问题。

开发构建：在完整源码仓库运行 `python scripts/build-astrbot.py --out <新的ZIP路径>`。构建只收录明确的插件文件，并附文件大小与 SHA-256 清单；拒绝覆盖已有 ZIP。完整开发报告见仓库 `docs/framework-evolution-2026-10-25/RESULTS.md`。
